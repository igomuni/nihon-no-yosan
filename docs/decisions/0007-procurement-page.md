# 0007 調達（落札実績）は、別のページとデータセットにする

日付: 2026-11-10。状態: 決定（暫定）。

## 決めたこと

- 調達ポータルの落札実績は、画面に**別のページ**「調達を観る」（`#/procurement`）として出す。予算の一生・RS のページには混ぜない。
- 画面用のデータは、`procurement/meta.json.gz` と、年度ごとの `procurement/{年度}.json.gz`。年度のファイルは、選んだときに読む。
- 利用条件は、`datasets/terms.json` に `p-portal.go.jp` を、新しい状態 `gov-terms-2.0`（政府標準利用規約 第 2.0 版に準拠）で記録する。
- ページの名前は「調達を観る」。載っているのは落札が決まった案件だけなので、ページの見出しの下に、その範囲を書く。
- 作り方・規則・検査は `docs/guides/procurement.md`。

## 理由

- **単位が違う。** 予算の一生は、項・目・事項と RS 事業の単位。落札実績は、案件（契約）の単位で、1 つの事業に複数の契約が対応する。同じ表に載せると、行の意味が混ざる。
- **つなぎが確かめられていない。** RS の支出先との照合には、法人番号が手がかりになりうるが、一致率を確かめていない。法人番号が空の行もある（2,841 行）。別のページなら、つながっていないことを、そのまま見せられる。
- **大きさが違う。** 全年度で 316,281 行（gzip で約 13 MB）。ほかのページの読み込みを重くしない。
- **既存の構成に合う。** ページごとにフォルダ（`trend/`・`mof/`・`lifecycle/`）を持ち、3 ペイン（フィルタ・一覧・詳細）で作る。

## 選ばなかった案

- **予算の一生のページに、調達のタブを足す。** 単位が違うので、タブの中でも別物になる。つなぎが確かめられていないのに、同じ画面にあると、つながった印象を与える。
- **ページ名を「落札実績」にする。** 範囲は正確に表せるが、ほかの調達情報（公告など）を足す可能性を残して、「調達を観る」にした。ほかの調達情報は、調べた範囲（2026-11-10）では、一括で取れる手段が見つかっていない（`procurement.md`）。
- **PDL1.0 の状態に入れる。** 調達ポータルの規約は、PDL1.0 ではなく、政府標準利用規約（第 2.0 版）に準拠すると書いている。別の状態にして、規約の本文のとおりに記録した。

## 変えるとき

- 公告などの他の調達情報が一括で取れるようになれば、このページに足すか、別のページにするかを、そのとき決める。
- RS との照合を作るなら、照合の規則と一致率を確かめてから、画面に出す（別の決定）。
- 公開サイトに載せるには、落札実績のデータセットを GitHub Releases に置く手順が要る（`procurement.md`）。
