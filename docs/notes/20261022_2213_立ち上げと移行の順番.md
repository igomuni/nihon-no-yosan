# 立ち上げと移行の順番

状態: 1 が完了（骨組み・CI・ドキュメントの規則・名前の揃え方）。2 は、純粋な関数の移動まで済み（下）。3 は、凍結と manifest まで済み（PR で確認）。次は、利用条件の未確認の分を確かめて公開するか、4。

1. 骨組み: workspaces・TypeScript・lint・テスト・CI、ドキュメントの規則、決めたこと（0001〜0003）。core の最初の関数として名前の揃え方。
2. core に、前のリポジトリ（marumie-rssystem）の純粋な関数を移す: 項・事項・目の鍵、名前でつなぐ処理、概算要求と予算書の突合の規則。テストも一緒に。
   - 済み: CSV と金額の読み方、概算要求書の木（目次・総表の小計の構造・位置の木）、明細表の項の範囲と目、予算書の額の列と項の鍵、`pairByName`、目のコード。前のリポジトリの fixtures の全件で、前の lib と出力が一致することを確かめた。
   - 4 に回す: 突合 M0〜M3 の組み立て（主体の対応、文書セット、項名の対応表、`NEAR_NAME`・`ZERO_AMOUNT`）。前のリポジトリでは build のスクリプトの中にあり、出力のバイト一致で確かめながら移す。
   - 5 に回す: 画面の行のキー（`mofRowKey`・`jikouKeyOf`）。画面のデータの型に依存する。
   - 移さない: `mof-keys`（V2 の予算書の正規化）と `match-key`（V1 の RS とのつなぎ）。0001 で V1・V2 を持ち込まないため。
3. 基準データ（原本の形の CSV）の初版を作る。manifest に SHA-256。利用条件を確かめるまで非公開。
   - 済み: `docs/guides/data.md` の「基準データの初版」。681 書、2,298 ファイル、283 MB。手元の `data/dataset/reference-v0/` と `datasets/reference-v0/manifest.json`。
   - 残り: 公開（Releases）。`datasets/terms.json` の `unconfirmed` 9 ドメインと、`search-summary` の 7 ドメインの規約のページ本文を読む。
4. pipeline の build を移し、前のリポジトリの出力とバイト一致を確かめる。
   - 済み: 突合 M0〜M3（`docs/guides/match.md`）。5 組・55 ファイルがバイト一致（`datasets/reference-v0/match-comparison.json`）。
   - 残り: 項の年度推移（`build-budget-request-trend-csv`）、事項要求の検知（`build-budget-request-jikou-youkyu`）、事項と目の年度推移（`build-budget-request-trend-detail-csv`）、概算要求と当初予算の差（`build-budget-request-mof-ui`）。後ろの 3 つは、前の build の出力（`tests/fixtures/budget-request-trend` など）に依存する。事項要求の検知は plain text を読む。
   - 比べ方を再現できる形で残す: 入力の版と SHA-256、比べた前のリポジトリの commit、比べるスクリプト（リポジトリに入れる）、結果。2 の全件比較はスクリプトを残さなかった（PR #2 のレビューの指摘）。
   - 入力の CSV の欠落・空のファイルを 0 件として通さない（`readCsv` は空でも `[]` を返す）。
5. apps/web に、概算要求の年度推移と、概算要求と当初予算の差の画面を移す。
6. 予算の一生の表（`docs/decisions/0003-budget-lifecycle-model.md`）のデータの契約をガイドで確定し、FY2023・FY2024 で作る。
7. extract（概算要求書の PDF からの CSV の作成）を移す。FY2028 の概算要求（2027 年 8〜9 月）より前に。

RS とのつなぎ、予算と RS をつなぐ画面は、6 のあと。
