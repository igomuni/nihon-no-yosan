## 1. 同じ「2025 年度版」が 2 通りある

「9月版」と「4月版」は、ファイル名は同じ（`*_RS_2025_*`）だが、中身が違う。

| 点 | 9月版（2024 と同じ形） | 4月版（これまでの洗い出しの対象） |
|---|---|---|
| 先頭の BOM | あり | なし |
| 見出しのかっこ・記号 | 全角（`（合計）`、`／`、`－`） | 半角（`(合計)`、`/`、`ー`） |
| NFKC で変わるセル | 718,873 / 10,738,201（6.7%）。全角かっこ 363,598、全角数字、全角スペース、`％` `／` `：` | **0** / 10,694,080 |
| 改行を含むセル | 8,921（ほぼ 3-2 の列） | 0 |
| 3-2 の列数 | 25 | 23（「派生元ー活動指標／成果指標」「派生先ー活動指標／成果指標」が無い） |
| 5-1 の行数 | 193,912 | 194,738 |
| 3-1 の行数 | 128,516 | 128,476 |
| 文章の例 | 「令和6年度ウェブ会議システム~新任管理者…」 | 「2024年度ウェブ会議システム新任管理者…」（元号が西暦に、`~` が無い） |
| 空白の例 | 「トラスト担当 政府認証基盤(GPKI)班」 | 「トラスト担当政府認証基盤(GPKI)班」（空白が無い） |

- 行の順序を問わず（NFKC で揃えて）比べても、5-2・5-3・5-4・6-1 でさえ、同じ行は 68〜93% にとどまる（5-2 89%、5-3 68%、5-4 84%、6-1 93%）。1-2・1-3・2-2・5-1 などは、さらに低い（5-1 は 1%）。元号→西暦、空白・記号の除去が、広い範囲の文章に及んでいる。
- 事業 ID の集合は同じ（どちらも 5,794 事業）。5-1 だけ、17 事業で、行が「4月版」にしか無い（旧の同じ事業の行と一致しない）。
- **どちらが元の配布物かは確かめていない。** 考えられるのは、(a) RS のサイトが、4 月（4月版）と 9 月（9月版）で、出力の仕様や中身を変えた。(b) 4月版は、旧リポジトリで取り込む途中に、NFKC・元号の西暦化・空白の除去・列の削除などの加工を受けた。(c) 各府省が、データを更新した。
- 旧リポジトリの記録（プロンプトログ 2026-04-30）に、`data/download/RS_2025` の zip を `data/year_2025` に展開した旨はあるが、加工の有無は書かれていない。

**この比較で直すこと:**
- 手がかりのメモ D 節の「RS のシステムか CSV の出力で NFKC 相当の変換がされている」は、**根拠が足りない**。9 月のダウンロード（2024・9月版）は正規化されていない。正規化されているのは「4月版」だけ。
- 同じく D 節の「改行を含むセルは 0」は、「4月版」の性質。9 月のダウンロードには、3-2 の列に改行がある（8,309〜8,921 セル）。改行・箇条書きの入力形式は、9 月のダウンロードで見られる。
- 公開しているデータセット `rs-v0`（1-2・2-1・2-2）と `rs-spend-v0`（5-1〜5-4）は、「4月版」から作った。`manifest.json` の「手を加えずに入れた」は、このリポジトリで手を加えていないという意味で、サイトの配布物そのままかは未確認。

- 事業名は、共通の 5,231 事業のうち 263 事業で変わった。名前を事業のキーにはできない（予算事業 ID を使う）。
- 9月版の検査用数字エラー（53 組・147 行）は、「4月版」の結果（53 組・147 行）と同じ。

## 3. サイトの現行の配布物との照合（2026-11-05）

`https://rssystem.go.jp/download-csv/2025` の ZIP 15 本（URL は `https://rssystem.go.jp/files/2025/rs/<ファイル名>.zip`）を、ブラウザのメモリ上で取得し（ファイルとしては保存していない）、サイズと SHA-256 を、手元の 9月版の ZIP と比べた。

| 比べたもの | 結果 |
|---|---|
| ZIP のサイズ | 15 本すべて一致 |
| ZIP の SHA-256（先頭 12 桁） | 15 本すべて一致 |
| ZIP の中の CSV の SHA-256 | 15 本すべて、9月版の CSV と一致 |
| 4月版（このリポジトリの `data/download/rs/2025/`）の CSV | 15 本とも、サイトの CSV と**一致しない**（行数・列・文字が違う、第 1 節） |

- **9月版は、サイトの現行の配布物と同一。** 4月版は、サイトの現行の配布物と違う。
- サイトのページに「データは 2026年1月19日時点のもの」とある。サーバーの `Last-Modified` は 15 本とも 2026-10-29 23:37:09 GMT（配信側の更新日で、データの時点ではない）。
- つまり、4月版は、(a) サイトが以前配っていた版、または (b) 取り込みの途中で加工された版。どちらかは、まだ確かめていない。

## 4. 1 本化の案

- **基準は、サイトの ZIP（= 9月版）にする。** 配布物そのままで、サイトの SHA-256 と照合できる（出どころが説明できる）。正規化（NFKC、空白、元号など）は、このリポジトリの処理として別に行い、規則を記録する。
- 切り替えると、これまでの 4月版から作ったものが変わる。画面の RS タブ（`rs/jigyo.json.gz`）、公開済みの `rs-v0`・`rs-spend-v0`、AI Data Stories の 5 本。変わる範囲は、先に差分で測る。
- 公開済みの `rs-v0`・`rs-spend-v0` の出し直しは、切り替えを決めてから（タグを変える）。

## 5. 4月版から9月版に切り替えたときの影響（RS タブのデータ）

現行の処理（`rs-link.ts`・`rs-jigyo.ts`）で、RS タブのデータ（`rs/jigyo.json.gz` の中身）を、4月版と9月版から作って比べた（作業用の出力で、リポジトリのデータは変えていない）。入力は 1-2・2-1・2-2。

| 入力 | 結果 |
|---|---|
| 4月版 | 事業 5,794、額の行 23,036、項に結べた行 33,260 |
| 9月版そのまま | 事業 5,794、額の行 23,036、項に結べた行 33,294。**額が読めない**（見出しが全角で、処理が期待する半角と合わない。額の行 23,036 のうち同じものが 0） |
| 9月版（見出しだけ NFKC） | 事業 5,794、額の行 23,036、項に結べた行 33,294 |

- **9月版は、そのままでは使えない。** 処理は、半角の見出し（`当初予算(合計)` など）を前提にしている。見出しの NFKC が最小限の前処理。
- **額（2-1）は同じ。** 4月版と9月版（見出しのみ NFKC）で、額の行 23,036 行がすべて一致した。
- **事業の名前は、245 事業で違う**（NFKC で揃えた後でも）。4月版は元号が西暦に、空白と `~` が除かれている（「令和7年度要求からは」が「2025年度要求からは」、「STI for SDGs の推進」が「STIfor SDGsの推進」、「/~浜通り地域等における復興知の集積と進化~」が「/浜通り地域等における復興知の集積と進化」）。事業 ID と府省庁は同じ。
- **項へのつなぎが変わる。** 状態の内訳のうち、`unmatched`（項名が予算書に無い）が、2024 年度は 17→0 行、2025 年度は 19→2 行に減る。`linked` は 12,902→12,919 行、14,031→14,048 行に増える。2021〜2023 年度は変わらない。
  - 原因は、4月版が項名の元号を西暦にしたこと（「令和2年度潜水艦建造費」が「2020年度潜水艦建造費」）と見られる。予算書の項名は元号のまま。`rs-link.md` が「予算書に同じ名前の項が無い理由は未確認」としていた 36 行は、これで説明できる（防衛省の国庫債務負担行為の項。推測ではなく、9月版で結べることを確かめた）。
  - 金額への影響は、6 事業・年度（防衛省の護衛艦、潜水艦、イージス・システム搭載艦など）で、結べる行が増え、結べた額の合計が約 5,480 億円増える（390.38 兆円 → 390.93 兆円）。ほかの事業・年度は、合計も行数も同じ。
  - 項へのつなぎが変わる事業は、NFKC で揃えた後でも 241 事業（結びのある 5,155 事業の 4.7%）。大半は、目名の文字（空白など）の違いで、合計額は同じ。
- 目名: 結べた行のうち目名のある行は 33,260→33,294、目に結べた行は 33,232→33,266。

**ここから言えること:**
- 9月版に切り替えると、事業の名前の一部（245 事業）と、項へのつなぎの一部（防衛省ほか）が変わる。額は変わらない。
- 切り替えは、見出しの正規化を前処理として入れれば可能。画面の表示への影響は、事業名の字面と、`unmatched` の減少が中心。

**まだしていないこと:** 3-1・3-2・4-1 を使う処理への影響の測定（5-x と AI Data Stories は第 6 節）。

## 6. 5-x（支出先）と AI Data Stories への影響

9月版を、段階的に前処理して、4月版と同じ処理にかけた（作業用の出力で、リポジトリのデータは変えていない）。前処理は、(C) 見出しだけ NFKC、(F) 見出しとセルを NFKC し、セルの前後の空白を除く。

### 6.1 9月版の 5-1 は、番号と金額のセルの後ろに空白がある

- 前後に空白のあるセルが 349,310 ある（すべて後ろの空白）。5-1 の「法人番号」157,729、「金額」98,537、「支出先の合計支出額」73,919、「ブロックの合計支出額」19,125。他のファイル・列には無い。
- 4月版には無い（取り込みの途中で取り除かれた、または 4月版の元データに無かった）。
- 影響: 空白を除かずに数値や番号を読む処理は、すべて失敗する。AI Data Stories の 15・18 の分析スクリプトは、(C) の入力で、結果が空になった（支出先の上位 0 件、契約方式の集計 0 件）。`rs-jigyo.ts` は空白を除いて読むので、RS タブのデータには影響しなかった。

### 6.2 5-x の伏せ字（`rs-spend-v0`）

9月版を (C) の前処理で `package-rs-spend.ts` にかけた（所要時間は 4月版と同じ約 2 分）。

| 項目 | 4月版（公開済み） | 9月版 |
|---|---|---|
| 5-1 の行数 | 194,738 | 193,912 |
| 伏せた名前の種類 | 4,395 | 4,751 |
| 法人番号がなく、残した名前 | 2,183 種類（18,434 行） | 1,877 種類（17,625 行） |
| 5-1 の名前を伏せた行 | 19,859 | 20,553 |
| 法人番号のある名前（規則 5 の根拠） | 20,319 | 20,434 |

- **伏せすぎが増える。** 4月版で残し、9月版で伏せた名前が 303 種類ある。すべて、全角英数字で書かれた外国の組織名（`ＡＡＩＣ　Ｐａｒｔｎｅｒｓ　Ａｆｒｉｃａ　Ｌｉｍｉｔｅｄ`、`ＮＥＣ　Ｃｏｒｐｏｒａｔｉｏｎ　Ｉｎｄｉａ　Ｐｒｉｖａｔｅ　Ｌｉｍｉｔｅ` など）。規則 4（英語の組織語）が、全角の文字に当たらない。9月版の番号なしの名前のうち、全角英数字を含むものは 2,971 / 6,504（46%）。
- **取りこぼしは増えない。** 4月版で伏せ、9月版で残した名前は 0 種類。逆方向（9月版だけで残した名前、18 種類）は、組織名（共同企業体など）。個人名の混入は確認していない。
- **9月版に切り替えるなら、規則の判定を NFKC 後の名前で行う必要がある**（置き換えは元の文字列に対して行う）。元号（令和6年度）や全角が残る自由記述の置き換えも、名前の一致を NFKC 後で行わないと、取りこぼしが出うる。

- つまり、LP の見出しの数字はほぼ変わらない。変わるのは、**名前の字面**（府省庁の空白、元号）と、**ラベル**（契約方式の名前）、**一部の件数**（4月版と9月版で 5-1 の行数が違うため）。

### 6.4 切り替えるなら必要な前処理（案）

1. 見出しとセルの NFKC（9月版は全角のかっこ・数字・スペースが多い）。
2. セルの前後の空白の除去（5-1 の番号・金額）。
3. 元号を西暦にする処理は**入れない**（予算書の項名と照合するには、元号のままのほうが結べる。第 5 節）。
4. 府省庁名の空白（「国土交通省 観光庁」）の扱いを決める（名前のキーとして、空白を除くか、そのまま持つか）。
5. `rs-spend` の伏せ字の判定を NFKC 後に行う。
