# AI Data Stories PoC（Claude Code 版）のまとめ

作成日: 2026-11-03（日本時間）
状態: 作業メモ。公開・実装を承認するものではない。
関連: `reference/20261102_0907_AI_Data_Stories_PoC_ChatGPT_Guideline.md`（ガイドライン）、ChatGPT 版の LP 2 つ（`reference/AI_Data_Stories_2017-2026_予算の増減*.html`）

## ファイルの構成

- `reference/`: 参考資料。ガイドライン（ChatGPT 用の指示文と観察項目）と、ChatGPT 版の LP 2 つ（ユーザーが ChatGPT で作ったもの。中身は変更していない）
- `index.html`: 26 本の目次（Artifact のリンク付き）
- `themes/NN_名前/index.html`: LP（Artifact に発行したものと同じ。`<html>` を含まない断片で、ブラウザで開ける。フォントは Google Fonts から読む）
- `themes/NN_名前/verify.md`: 検算の記録
- `themes/NN_名前/scripts/`: 分析・検算・LP 生成のスクリプトとひな形（中間の JSON は含めない。スクリプトは `data/` と `apps/web/public/data/` を読む）
- `themes/00_予算の10年/preview.html`: 1 本目をそのまま開ける形にしたもの

## 何をしたか

ガイドラインの手順を、このリポジトリのデータと関数で行った。

- 1 本目: 「この 10 年で、どんな予算が増えて、どんな予算が減っているか」（ユーザーの関心）→ 親（Claude Code 本体）が分析して LP を作った。
- 2〜26 本目: 「次に掘ると良さそうな問い」と新しいテーマから、サブエージェント（Opus 5.5）を 5 本ずつ同時に走らせた。5 回で 25 本。親は、数値の抜き取り検算、表示の確認、Artifact の発行、目次の更新を行った。
- 発行した Artifact は 26 本と目次 1 本。すべて非公開（2026-11-03 時点）。目次: https://claude.ai/artifact/RGyztZ198jsmkRfYmGiRa7
- 各テーマの LP・検算の記録（`verify.md`）・スクリプトは `themes/` の下。回ごとの手順・検算・直したことは `20261103_2309_ループの記録とハーネスの案.md`。

## 観察したいことへの答え

### 1. 全量のデータを、どこまで探索できたか

- 入力は、`npm run build:data` が読む 3 つ（基準データ `reference-v0`、過去年度 `mof-history-v0`、RS 2025 年度版の CSV 15 ファイル）。manifest・`inputs.json` の SHA-256 で、全ファイル（2,298・143・15）の一致を確かめた。読めなかったものは無かった。
- 使ったのは、画面用の JSON（`apps/web/public/data/`）、元の CSV、このリポジトリの関数（`packages/core`）。PDF の原本は使っていない（基準データの PDF から取り出したテキスト・表だけ）。
- 手元の `reference-v0` は、Release（2,249 ファイル）より 49 ファイル多い（manifest の SHA-256 が違う）。何が増えたかは確かめていない。ユーザーの指示で、手元の版を使った。
- ChatGPT 版との違い: ChatGPT は、Release の tar.gz をローカルから手動でアップロードして、CSV・JSON・TXT を探索した。こちらは、展開済みのファイルを、スクリプトとこのリポジトリの関数で直接集計できた。

### 2. 漠然とした関心と、明確な調査目的の両方に対応できたか

- 1 本目の関心（「増えた予算と減った予算」）は漠然としていたが、インタビューは挟まず、分析に入った（ガイドラインの手順 2 の「調べたいことが明確なら、質問を挟まず分析へ」に従った）。
- その後の関心は、「所管ごとに見ると」「ほかのテーマ」と具体的になり、各回のテーマ選びは、LP が出した問いを材料にした。
- 未検証: 関心が本当に曖昧なままのとき、自然なインタビューでテーマを見つけられるか。今回は試していない。

### 3. 数値・出典・意味を検証できるか

- 26 本すべてに、`verify.md`（どの数値を、どう別の方法で確かめたか、未確認の点）がある。LP には、根拠のタグ（原資料・加工・AI の計算・解釈）を付けた。
- 親の抜き取り検算: 主要な数値を、元の CSV から直接足し直して確かめた（FY2020 の決算、予備費の使用額 25.97兆円、特別会計 8 年の現額・不用、地方へ渡るお金 33.89 → 41.82兆円、財投の FY2021 当初 72.62兆円など）。すべて一致した。
- 回をまたぐ一致: 同じ数値を別のテーマが出す形（交付金の締め 18.33/15.06/3.27、利子及割引料、公庫出資 10.39 など）で、食い違いを見つけやすかった。
- 検証で見つけた誤り（親が直した）:
  - 特別会計の地図: 積み上げ棒の目盛りの最大値が固定値で 1 桁違い、棒が天井に張り付いた。エラー・NaN のチェックでは見つからない。
  - グラフの要素の、描画範囲からのはみ出し（3 か所）。自動チェック（bbox が viewBox の内側か）で見つけた。
  - 国債の利子の額が、テーマによって 16.46兆円（国債整理支出の項）と 16.6兆円（3 項の計）で違った。含めた項の違いで、特別会計の地図に書き足した。
  - 画面用の目のデータの補正の差引額（`suppNet`）は、補正が複数回ある年度で最後の回の分だけ。防衛費の中身の「未確認」の差（FY2018 7.9億円・FY2020 39.8億円）の原因だった。本文を直した。
- 限界: 検算は、同じデータの別の読み方での一致。政府が公表する集計値との照合は、ほぼしていない。LP に「照合していない」と書いた。

### 4. LP をきっかけに、新しい問いや利用者の意見が生まれたか

- 各 LP の「次に掘ると良さそうな問い」から、次の回のテーマが生まれた（例: 予算の一生 → 予備費の行方・使い切れない予算 → 交付金の行方 → 移し替えの地図）。
- 利用者の意見の取り込み: 今回は、ユーザーが LP 全体の方向（所管ごとに見る、ループを回す）を決めた。個々の LP に対する意見の収集は、していない。

## ChatGPT 版との比較（1 本目だけ）

| 観点 | ChatGPT 版 | Claude Code 版 |
|---|---|---|
| 入力 | 項の CSV（`kou-general.csv`） | 項・目・事項・分類コード・RS（このリポジトリの処理を通したもの） |
| 増減の単位 | 項の名前が完全一致するもの（両年度で 618 項） | 主要経費別・使途別の分類コード |
| 根拠の追い方 | 元 CSV の行番号まで画面で追える | 根拠の種類のタグ。行番号は出さない |
| 操作 | 所管・項を選んで深掘りできる | 読み物が中心。ホバーで年度ごとの値 |
| 数値 | 一般会計の当初予算 97.455 → 122.309兆円 | 同じ値 |

比較は、完成した LP 2 つの HTML を読んだ範囲。ChatGPT のセッション自体（共有リンク）は、開けなかった。

## 使用量

- Opus 5.5 のサブエージェント 25 本（1 本あたり約 40〜60 万トークン）で、5 時間の枠に当たった。5 回のうち 2 回で、途中で止まった（SendMessage で、止まったところから再開できた）。
- 親（本体）は、検算・表示確認・発行・目次を担った。

## 注意（公開するとき）

- 利用条件: RS 由来のテーマ（AI と人工知能、交付金の行方、お金の行き先、基金へのお金、契約の方式と入札、防衛の契約、研究開発の基金）は、LP に出典と加工の表記を入れた（出典：行政事業レビュー見える化サイト（https://rssystem.go.jp）を加工して作成）。それ以外は、財務省「予算書・決算書データベース」を加工して作成、と書いた。ガイドラインは、データパックの再配布や外部 AI へのアップロードの権利確認を、別に扱うとしている。今回の Artifact は、非公開。
- 個人: 支出先は、法人と公的機関だけを出した（個人事業主などは、集計に含めても名前を出さない）。
- 未確認: Artifact のホスト（claude.ai）に載せることの、データの利用条件上の扱い。
