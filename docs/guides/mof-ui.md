# 概算要求と当初予算の差（FY2023〜FY2026）

概算要求額と、予算書の当初予算額（国会への提出時の政府案）を、項ごとに並べる。事項・目は名前でつなぐ。差の理由の型を付ける。対象は FY2023〜FY2026（FY2027 は予算書が無い）。出力は画面用の JSON（`kou.json.gz`、`detail.json.gz`）と件数の記録（`summary.json`）。実装は `packages/pipeline/src/build/mof-ui.ts`、動かすのは `mof-ui-cli.ts`、型は `packages/core/src/budget-request-mof.ts`、事項・目をつなぐ関数は `packages/core/src/pair.ts`。画面の仕様は、画面を移すとき（移行の 5）に別のガイドで書く。

```bash
node packages/pipeline/src/build/mof-ui-cli.ts data/dataset/reference-v0 <出力ディレクトリ>   # kou.json.gz、detail.json.gz、summary.json
```

年度推移（`docs/guides/trend.md`）には、予算書との突合を混ぜない。この build は別の出力で、予算書側の値を持つ。

## 入力

CLI は、次を基準データから作り直して入力にする。

| 入力 | 使い方 |
|---|---|
| 突合の `m1-kou.csv`・`unmatched-mof-kou.csv`（`docs/guides/match.md`）。予算書の版は下の表 | 項の対応、予算書にだけある項 |
| 突合の `request-kou.csv`（要求の年度と同じ版の突合） | 要求側の所属と前年度予算額。`2025_teishutsu` の突合には無いので、`2025` のものを使う |
| 項の年度推移の `kou.csv`（`trend.md`） | PDF の頁、行の識別 |
| 事項要求の検知の `kou.csv` と `jikou.json.gz`（`jikou-youkyu.md`） | 差の理由の型（事項要求・要求0・一括計上・組織の事項要求） |
| 事項・目の年度推移の `jikou.csv`・`moku/{年度}.csv`（`trend-detail.md`） | 詳細の要求側の事項・目 |
| 基準データの `mof-archive/{版}/{kou,jikou,moku}-{general,special}.csv` | 予算書の項・事項・目 |
| 基準データの `budget-request/{年度}/pdf-corpus-freeze.json` | 要求書の URL |

**予算書の版**は、すべて提出時（政府案）にそろえる。

| 年度 | 版 |
|---|---|
| FY2023 | `2023` |
| FY2024 | `2024` |
| FY2025 | `2025_teishutsu`（成立後の `2025` は使わない。国会で修正された年度） |
| FY2026 | `2026` |

## 行（`kou.json.gz`）

1 行 = 年度 × 予算書の項。型は `BudgetRequestMofRow`。

| 種類（`kind`） | 内容 |
|---|---|
| `matched` 対応あり | MATCHED / NEAR_NAME の予算書の項。同じ項に複数の要求行が対応するとき（複数の府省の書に載る項、復興特会の持ち分）は 1 行にまとめる。要求額は最も大きい額（合計書）、要求書は書ごとに `books` に持つ |
| `mofOnly` 予算書のみ | `unmatched-mof-kou.csv` |
| `reqOnly` 概算要求のみ | NO_CANDIDATE の要求行。要求側の所属＋項名でまとめる |
| `zero` 額0の項 | ZERO_AMOUNT の要求行（前年度・要求とも 0） |

**差** は、当初予算額 − 要求額（正なら要求より予算が大きい）。差の計算は画面の側。

| 年度 | 版 | 対応あり | 予算書のみ | 概算要求のみ | 額0の項 |
|---|---|---:|---:|---:|---:|
| FY2023 | `2023` | 956 | 87 | 16 | 46 |
| FY2024 | `2024` | 968 | 66 | 13 | 39 |
| FY2025 | `2025_teishutsu` | 1,013 | 47 | 13 | 42 |
| FY2026 | `2026` | 1,035 | 49 | 9 | 42 |

全体で 4,441 行、要求書の URL は 380。

**前年度予算額:** 概算要求書は前年度の当初予算額を、予算書は前年度の**補正後**の額（補正予算の改予算額）を載せる。例: 消費者庁共通費 FY2026 の予算書の前年度予算額 5,232,537 千円は、概算要求書の前年度予算額 5,212,333（FY2025 の当初）と違う。補正で額の変わった項で、両者は違う。前のリポジトリは、FY2026 の予算書の前年度予算額について一般会計 824 項のうち 556 が補正後の額に一致する、と記録している。今回は数え直していない（未確認）。

## 事項・目（`detail.json.gz`）

行のキー（`mofRowKey` = `年度|種類|会計|所管|府省|勘定|組織|名前`）→ 内訳（`BudgetRequestMofDetail`）。各行は `[名前, 目のコード, 要求額, 当初予算額]`（千円）。無い側は null。つなぐ処理は `pairByName`（`docs/guides/keys-and-pairing.md`）。

- **要求側:** 年度推移の事項・目（`jikou.csv`、`moku/{年度}.csv`）。目は分冊の明細表から取っており、総表の書とは書が違うので、要求書ではなく項の識別（会計区分＋所管（特別会計は特別会計名）＋勘定＋組織＋項名）で引く。同じ予算書の項に複数の要求行が対応するときは、要求額の最も大きい行（合計書）の内訳だけ。年度推移の内訳は、同じ項が複数の府省の書に載ると書ごとに行を持つので、要求書の公開元（ドメイン）がその行と同じものだけを取る（取らないと、書の数だけ足してしまう）。統合は、要求の項ごとの内訳を足す。要求側の内訳が取れない項は `noReq: 1`（要求の列は全部 null）。
- **予算書側:** `{jikou,moku}-{general,special}.csv`。項の識別は、一般会計が所管＋組織＋項コード＋項名、特別会計が特別会計＋勘定＋項コード＋項名（どちらも項の CSV で一意。重複や項の無い行があれば止まる）。
- **目:** 予算書の目は項ごと（事項をまたいだ額）なので、要求側も事項をまたいで目名で足す。予算書に事項 × 目の額は無い。
- **つなぐ鍵は名前**（幅と空白をそろえたもの）。目のコードは分類で、1 つのコードに複数の目が入るので鍵にしない。コードが同じで片側に 1 つずつ残る目は、組にしない。
- **目のコード:** 主要経費＋目的別-目別（例: `95016-16`）。中段（財政法・経済性質・使途）は、特別会計の要求書の原文と予算書とで桁の取り方が違うので使わない。
- **並び:** 予算書の順。要求にだけある行は、同じコードの予算書の行の後ろ（無ければ末尾）。

対応ありの項の事項・目の一致の数は、`summary.json` の年度ごとの `jikou` / `moku`（`kou` 項の数、`sameSet` 集合が同じ項、`bothEq` / `bothNe` 両側にあり額が同じ / 違う、`reqOnly(Zero)` 要求のみ（うち要求額0）、`mofOnly(Zero)` 予算のみ（うち当初0））。

| 年度 | 対象の項 | 目: 集合が同じ項 | 両側・同額 | 両側・額が違う | 要求のみ（うち0） | 予算のみ（うち0） |
|---|---:|---:|---:|---:|---:|---:|
| FY2023 | 956 | 735 | 3,173 | 4,150 | 398（276） | 249（83） |
| FY2024 | 968 | 763 | 3,020 | 4,338 | 314（273） | 136（69） |
| FY2025 | 1,013 | 757 | 2,989 | 4,710 | 364（266） | 241（71） |
| FY2026 | 1,035 | 801 | 3,089 | 4,679 | 454（376） | 151（88） |

要求書は額のない目も載せるので、要求のみの目の多くは要求額 0。

## 差の理由の型

読み方の手がかりで、理由を確定するものではない。

| 型 | 付け方 |
|---|---|
| 事項要求 | 事項要求の検知（`jikou-youkyu.md`）の形が `印` か `文` |
| 組織に事項要求 | `jikou.json.gz` の `orgs` に、その組織がある |
| 要求額0 | 検知の形が `要求0` / `要求0・場所ごと` |
| 一括計上 | 検知の形が `一括計上`（概算要求のみの行。例: 国際観光旅客税財源観光振興推進費） |
| 一括計上の配分先 | `要求0` のうち、同じ所管・組織に一括計上の項がある年度のもの（例: 国際観光旅客税財源観光振興費） |
| 編成で決まる | 項名が `予備費` / `国債費` / `地方交付税交付金` / `地方特例交付金` を含むか、`繰入` で終わる |
| 複数書 / 持ち分 | 同じ予算書の項に、複数の書の要求行が対応する。額が違えば持ち分（東日本大震災復興の各省の書と合計の書）。額が同じで、同じ府省（公開元のドメイン）の書どうしなら複数書。複数所管で額が同じ項には付けない。額の取れない書（総表の無い分冊）は比べない |
| 名前が近い | NEAR_NAME（予算書の項名が少し違う。行に予算書の項名 `mofName` を持つ） |
| 改称 | 突合の項名の対応表（`reason` = `kou_renamed`）でつないだ |
| 統合 | 複数の要求の項が、1 つの予算書の項に対応する。名前の違う項（項名は「A ＋ B」）と、同じ書の項コード違いの同名の項。要求額・前年度予算額は、要求の項ごとの値を足す |

**要求行と型の結びつけ:** 年度推移の行を、要求書＋項コード＋項名で引く。同じ書に同名同コードの項が複数あるときは、組織か勘定で絞る。事項要求・要求0・組織の事項要求は、その行の識別（会計区分＋所管＋勘定＋組織＋項名）で引く。

**編成で決まる項の重み:** 編成で決まる項に当たる対応ありの項は、各年度で約 1 割（FY2023〜FY2026 で 107 / 118 / 120 / 126 項、11〜12%）。差の絶対値の合計に占める割合は、79% / 59% / 38% / 60%（動かした出力から数えた。FY2025 は提出時の版）。

## 具体例（FY2026 の消費者庁共通費）

`kou.json.gz` の 1 行: 対応あり、所管 内閣府、組織 消費者庁、要求額 5,459,347、当初予算額 5,585,108、要求書の前年度予算額 5,212,333、予算書の前年度予算額 5,232,537（千円）、型なし。要求書は 1 冊（目次の頁 5、PDF 頁 7）。事項 1、目 23。

`detail.json.gz` の同じ行: 事項 `消費者庁一般行政に必要な経費` は要求 5,459,347・当初 5,585,108。目の最初は `職員基本給`（`95016-02`）で要求 2,429,812・当初 2,468,355、次が `職員諸手当`（`95016-03`）で要求 1,271,359・当初 1,344,403。
