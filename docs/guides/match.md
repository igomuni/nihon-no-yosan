# 予算書 × 概算要求の突合（M0〜M3）

予算書（財務省。項・事項・目）と、概算要求書（目次・総表・明細表）を、名前で対応づける。実装は `packages/pipeline/src/build/match.ts`、動かすのは `match-cli.ts`。入力は基準データ（`docs/guides/data.md`）。概算要求書の木の作り方は `docs/guides/budget-request-tree.md`、鍵と名前の揃え方は `docs/guides/keys-and-pairing.md`・`docs/guides/names.md`。

```bash
node packages/pipeline/src/build/match-cli.ts data/dataset/reference-v0 <概算要求の年度> <予算書の版> <出力ディレクトリ>
```

組（概算要求の年度, 予算書の版）: (2023, 2023)・(2024, 2024)・(2025, 2025)・(2025, 2025_teishutsu)・(2026, 2026)。予算書の版は、`2023`＝令和5年度、`2024`＝令和6年度、`2026`＝令和8年度が国会への提出時、令和7年度だけ `2025_teishutsu`＝提出時と `2025`＝成立後の 2 版。

## 原則

- **名前は、揃えてからの完全一致。** 揃えるのは幅の統一と、確かめた PDF の外字、空白だけ（`names.md`）。部分一致・読み替えはしない。例外は、下の項名の対応表（`KOU_RENAMES`）と組織名の読み替え（`RENAMES`）だけ。
- **コードは対応づけに使わない。** 概算要求の項コード（3 桁）は、予算書の項コードと一致しない。事項の主要経費別分類コードは、一致を裏づけの列に記録するだけで、除外に使わない。
- **金額は対応づけに使わない。** 診断の列（`amount_diff` ＝ 概算要求額 − 予算書の額、など）にだけ使う。概算要求（要求時）と予算書は別時点の額で、不一致は失敗ではない。例外は、`NEAR_NAME` と `ZERO_AMOUNT`（下）で、これらは対応を決めるのではなく、確認用に分ける。
- 候補が複数のときは**絞らず**、候補ごとに 1 行ずつ記録する。
- 上位の層が一意に対応しなかったときは、下位は探さない（`PARENT_UNMATCHED`）。

## 層

| 層 | 概算要求側 | 予算書側 | 根拠 |
|---|---|---|---|
| M0 主体 | 明細表の `CONTEXT`、目次の（所管／会計／勘定／組織） | 所管・組織・特別会計・勘定 | 名前の完全一致 |
| M1 項 | 項 | 項（kou） | 範囲の中での項名の完全一致 |
| M2 事項 | 項に続く事項 | 事項（jikou） | 一致した予算書の項の中での事項名の完全一致 |
| M3 目 | 明細表の目 | 目（moku） | 一致した予算書の項の中で、**項ごとに集約**してから対応づける |

- 一般会計は（所管, 組織, 項名）、特別会計は（特別会計, 勘定, 項名）で予算書の項を探す。同じ名前が複数あれば複数候補になる（復興庁の共管など）。
- 組織が分からない書（目次なし）の一般会計は、所管と項名で探す。候補が複数なら、総表の行の並びから決めた組織で絞る。絞って 1 つ以上残れば、その候補を使う。
- **M3 の集約:** 予算書の目は項単位で、事項の列がなく、項内の複数の事項にまたがる合計になり得る。概算要求の目の行を（主要経費 2 桁＋目的別 3 桁、`x`、目別、目名）で足し合わせ、予算書の目に多対一で対応づける。`x` の桁数で読みが決まる: 4 桁＝財政法＋経済性質別＋使途別（一般会計だけ）、3 桁＝経済性質別＋使途別、1 桁＝使途別（特別会計）。それ以外は `code_form_unknown`。最後の 4 桁（`zz`）に対応する予算書の列はなく、比べない。

## 概算要求側の階層と、会計・所管の決め方

階層（所管・会計・組織・勘定 › 項 › 事項）は、書ごとに `budget-request-tree.md` の 4 つのどれかで作る。さらに、書をまたぐ付け方がある。

1. **文書セット（追補 A）:** 目次・総表・明細表が別の PDF に分かれる書（文部科学省など）。目次を持たない書を、同じファミリー（書の名前の末尾の数字を除いた共通部分）の目次の書に、項（コード＋名前）の一致で付ける。付く先がちょうど 1 つのときだけ。付いた組は `sets.csv`。付いた書の総表・明細表の行は、付け先の書の行の後ろに続ける（番号順）。
2. **総表の木に付ける（追補 D）:** 目次にも付かなかった書のうち、総表を持つものは、総表の行の並びで木を作る。明細表だけの書を、その木に付ける（同じ規則）。
3. **明細表の木（追補 E）:** それでも付かなかった明細表だけの書は、自分の明細表の行の並びで木を作る。
4. **目次から漏れた項:** 総表から補う（`supplementTocTree`）。補った項の `hierarchy` は `toc_total`。

**会計の種類（一般／特別）と所管・特別会計** は、書の最初の明細表の `CONTEXT`（`NN 〇〇所管`＝2 桁で一般会計、`NNNN 〇〇特別会計`＝それ以外で特別会計）から取る。所管は「所管」より前、特別会計は「特別会計」より後ろを落とした名前。明細表に `CONTEXT` が無い書は、次の順で補う。

- 総表の木の書: 同じファミリーの他の書の `CONTEXT` が 1 種類だけなら、それを使う。
- それでも無い書（明細表のヘッダが読めない抜粋版）: 表紙（`cover/sources/{slug}.csv`）の `HEADER` 行の `name` から。括弧内は組織の候補で、`金融庁（金融庁）` のような重複は 1 つにする。予算書の組織にあるときだけ使う。
- どれでも決まらなければ、その書は対象外（`no_context`）。

**組織名の読み替え（`RENAMES`）:** 予算書の呼び方に合わせる。FY2023 の厚生労働省の 国立更生援護機関・国立更生援護所 → 国立障害者リハビリテーションセンター。

## 項の補助の分類

- **項名の対応表（`KOU_RENAMES`、`reason` = `kou_renamed`）:** 名前で候補が見つからない一般会計の項に、所管|組織|項名の完全一致で、予算書の項名を対応させる。原文と予算書の目で確かめた組だけ。FY2023 のこども家庭庁（2023 年 4 月発足）は、概算要求（2022 年 8 月）が仮の項名で、予算書で確定した。
  - 改称: 保育等対策費 → 保育対策費、国立児童自立支援施設施設整備費 → 国立児童自立支援施設整備費、児童福祉施設整備費 → 児童福祉施設等整備費
  - 統合（2 つの要求の項が 1 つの予算の項に）: 国立児童自立支援施設費・同 運営費 → 国立児童自立支援施設、こども家庭推進費・こども家庭調査研究等推進費 → こども政策推進費
  - 額は一致しない（保育等対策費の目の就学前教育・保育施設整備交付金は、予算書では児童福祉施設等整備費へ）。
- **額0の項（`ZERO_AMOUNT`）:** 総表で前年度予算額・概算要求額がともに 0 と印字された項（空欄は含めない）。要求書は額のない科目も項として載せる。
  - 候補がないものは、名前が見つからないのではなく額のない科目なので、`NO_CANDIDATE` と分けて `ZERO_AMOUNT`（`zero_prev_and_request`）にする。
  - 同じ予算書の項に、額のある項も対応しているときは、額0の項の対応を外して `ZERO_AMOUNT`（`zero_duplicate_of_nonzero`）にする。同名の額0の項が別の所属にあるときに起きる。
  - 額0の項だけが対応する予算書の項は、対応のまま残す（予算書にも額 0 の項がある。要求が 0 で編成で額が付く項もある）。
- **名前が近い組（`NEAR_NAME`、`reason` = `name_near`）:** 候補なしの項と、どの項にも対応していない予算書の項で、次をすべて満たし、両側で 1 対 1 に決まるもの。`MATCHED` には数えない。表記ゆれの確認用。
  - 所属（所管＋組織、または特別会計＋勘定）が同じ。
  - 名前が 6 文字以上で、編集距離が 2 以内。
  - 概算要求額と予算書の額の差が、予算書の額の 5% 以内。
  - 1 つの予算書の項に複数の概算要求の行が当たるのは、同じ名前のとき（同じ項が複数の府省の書に載る）だけ許す。

## 出力

| ファイル | 内容 |
|---|---|
| `m0-entities.csv` | 主体の対応（`request_source`, `level`, `request_code_name`, `request_name`, `mof_key`, `status`, `reason`） |
| `request-kou.csv` | 概算要求の木だけから決めた項の所属（予算書の判定を使わない）と、総表の額 |
| `m1-kou.csv` | 項。概算要求側（`request_source`, `toc_kou_idx`, `request_code3`, `request_name`, `request_page`）、予算書側（`mof_row`, `mof_name`）、`candidate_count`, `status`, `reason`, 診断の金額（`request_amount`, `mof_amount`, `amount_diff`）、`request_scope`, `hierarchy` |
| `m2-jikou.csv` | 事項。`request_no`, `request_code`（`NN-NN`）, `mof_kou_row`, `mof_jikou_row`, `class_code_agrees`（後半 `NN` が主要経費別分類コードと一致）ほか |
| `m3-moku.csv` | 目（集約後）。`code_main_purpose`, `code_x`, `code_item`, `request_rows`, `request_sum`, `mof_kou_row`, `mof_moku_row`, `mof_amount`, `amount_diff` ほか |
| `unmatched-mof-{kou,jikou,moku}.csv` | 概算要求側のどの行にも対応づかなかった予算書の行。`reason`: `no_request_row`（項）、`kou_matched_no_request_row`、`kou_not_matched`（事項・目） |
| `sets.csv` | 文書セットで付いた組（`toc_source`, `attached_source`, `matched_kou_keys`） |
| `request-no-toc.csv` | 木を作れなかった書の行（`OUT_OF_SCOPE`／`no_toc`） |
| `summary.json` | 層ごとの `status` の件数、予算書の網羅、概算要求側の自己整合、入力の SHA-256（`input_sha256`） |

- 予算書の行の id は `{表}:{行番号}`（例 `kou-general:37`。行番号は CSV のデータ行の 1 始まり）。
- `status`: `MATCHED`（候補が 1 つ）、`AMBIGUOUS`（2 つ以上。候補ごとに 1 行）、`NO_CANDIDATE`、`PARENT_UNMATCHED`（上位が一意に対応せず探していない）、`OUT_OF_SCOPE`（`no_context` など）、`NEAR_NAME`、`ZERO_AMOUNT`。
- `summary.json` の `input_sha256` は、入力ファイルごとの `{種類}/{ファイル名}\t{SHA-256}`（概算要求）と `mof/{名前}.csv\t{SHA-256}`（予算書）を改行でつないだものの SHA-256。

## 限界と注意

- 概算要求側に PDF が無いため対応づかない項がある（日本学術会議は「事項要求」で金額つきの要求書が無い、など）。
- 一致しなかった行の大半は、予算書の同じ範囲に名前が無いもの（概算要求の項目が予算案で統合・改称・新設された等）。
- 同じ予算書の行が、複数の概算要求の書から対応づくことがある（電源開発促進勘定を複数の省庁の PDF が載せる等）。
- 概算要求の目を予算書の目に対応づけたあと、集約した合計と予算書の金額が一致する割合は低い（別時点の額）。

- **前のリポジトリの出力とのバイト一致:** `node packages/pipeline/src/migrate/compare-match.ts <基準データ> <前のリポジトリ> <commit> <結果の JSON>`。5 組・55 ファイルすべてがバイト一致した。結果は `datasets/reference-v0/match-comparison.json`（比較先の commit、組ごとの入力の SHA-256、ファイルごとの SHA-256）。
  - 比較先は、前のリポジトリの `3aef2de9` の `tests/fixtures/mof-budget-request-match/{版}/`。前のスクリプトを、前の fixtures から動かした出力も、この 55 ファイルとバイト一致した（基準線）。
  - 基準データの入力を 1 行書き換えると、違いを検出する（負の確認）。
