# 項・事項・目の鍵と、名前でのつなぎ方

概算要求書と財務省の予算書の項・事項・目を見分ける鍵と、両側の事項・目を名前でつなぐ規則。実装は `packages/core/src/mof.ts`（予算書の列と鍵、目のコード）、`packages/core/src/request-tree.ts` の `kouKey`、`packages/core/src/pair.ts`（つなぎ方）。

名前は、どの鍵でも `nameKey`（`docs/guides/names.md`）で揃える。コードは原文のまま。鍵の区切りは `|`。

## 鍵

| 鍵 | 形 | 一意の範囲 |
|---|---|---|
| 概算要求の項（`kouKey`） | 項コード（3 桁）\|項名 | 1 つの書の中で照合に使う。概算要求の 3 桁は予算書の項コードと一致しないので、予算書との突合には使わない |
| 予算書の項（`mofKouKey`） | 一般会計: 所管\|組織\|項コード\|項名。特別会計: 特別会計\|勘定\|項コード\|項名 | 1 つの版の項の CSV で一意。事項・目の CSV も同じ列を持つので、同じ鍵で項に結ぶ |
| 予算書の項を名前で探す鍵（`mofKouNameKey`） | 一般会計: 所管\|組織\|項名。特別会計: 特別会計\|勘定\|項名 | 一意でない（同じ名前の項が複数あり得る）。候補を探すときに使う |
| 目のコード（`mofMokuCode` / `reqMokuCode`） | 主要経費＋目的別-目別（例: `95016-16`） | 一意でない（分類なので、1 つのコードに複数の目が入る）。鍵にせず、並べる位置と表示にだけ使う |

**目のコードの中段を使わない理由:** 要求書の目のコードは `95016-2111-02-0000` のように 4 つに分かれるが、中段（財政法・経済性質・使途）の桁の取り方が、特別会計の要求書の原文（`65061-9-18`）と予算書（財政法の列が無い）とで違う。`reqMokuCode` は 1 つ目と 3 つ目だけを取る。複数のコードが「、」で並ぶときは最初のもの。

## 予算書の額の列

本年度の額（千円）は、列名で探す。

| 表 | 列 |
|---|---|
| 項（`mofAmountKou`） | `令和N年度要求額` / `予定額` で始まり、`の合計` で終わる列 |
| 事項（`mofAmountJikou`） | `令和N年度要求額` / `予定額` で始まる最初の列 |
| 目（`mofAmountMoku`） | `令和N年度要求額` / `予定額`（末尾の `(千円)` は任意）で終わる列 |

## 名前でつなぐ（`pairByName`）

1 つの項の事項（または目）を、要求側と予算書側でつなぐ。

1. 片側ずつ、同じ名前の行の額を足す。コードは最初の行のもの。空欄の額は、もう一方の行に額があればその額、どちらも空欄なら空欄のまま。
2. 予算書の順に並べ、同じ名前が要求側にあれば組にする。
3. 要求にだけある行は、同じコードの予算書の行のうち最後のものの後ろに置く。同じコードが無ければ、末尾に要求の順で置く。
4. 組の額は、名前のある側の空欄を 0、名前の無い側を `null` にする（「その側に無い」と「額が 0」を分ける）。

コードが同じで片側に 1 つずつ残る行も、組にしない。改称のことも、別の目への差し替えのこともあり、名前の違う行を同じとする根拠がデータに無いため。

**使う範囲:** 画面で両側の事項・目を並べるための処理。名前のある側では、原本の空欄と 0 が同じ 0 になり、区別が消える。予算の一生の表（`docs/decisions/0003-budget-lifecycle-model.md`。空欄と 0 を区別する）の値には使わない。そちらは原本の値を `amount` で読み、空欄を null のまま持つ。
