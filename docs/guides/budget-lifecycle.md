# 予算の一生の表のデータの仕様（案。レビュー前）

状態: **案**。実装の前にレビューを受ける。方針は `docs/decisions/0003-budget-lifecycle-model.md`（項と出来事を分ける、額は円と原本の値を両方持つ、値の状態を分ける、年度をまたぐ対応は別の表、最初は FY2023・FY2024）。この文書は、その方針を、列・鍵・単位・検算まで具体にする。数字は、基準データ（`data/dataset/reference-v0/`）の FY2023・FY2024 から数えた。

目的: 1 つの項について、概算要求 → 政府案（予算書）→ 成立 → 補正 → 決算を、同じ年度の中で、額でつないで追えるようにする。要求から決算までの額の変化（ブリッジ）と、決算の現額の内訳（サンキー）の土台にする。

範囲（この仕様の第 1 段）: 項の粒度、FY2023〜FY2027（年度ごとに、基準データにある段階だけ。「対象年度と入力」）、一般会計・特別会計。目・事項、RS（事業）、図は含まない。

## 入力

| 出来事 | 入力（基準データ） | 単位 | 備考 |
|---|---|---|---|
| 概算要求 | 概算要求書から作った項（`docs/guides/trend.md`）と、予算書の項への突合（`match.md`、`mof-ui.md` の行の規則） | 千円 | 要求額と、要求書が載せる前年度予算額 |
| 政府案 | `mof-archive/{年度}/kou-{general,special}.csv` | 千円 | 国会への提出時の予算書。列名は版で違う（`令和5年度要求額(千円)の合計`、特別会計は `…予定額…`、`令和6年度要求額の合計` など。単位はどれも千円）。前年度予算額の列を持つ |
| 成立・補正 | `mof-archive/{年度}/kou-{general,special}-hosei.csv` | 千円 | 成立予算額、補正の追加額・修正減少額・差引額、改予算額（補正後） |
| 決算 | `mof-archive/{年度}/kou-{general,special}-kessan.csv` | **円** | 歳出予算額、前年度繰越額、予備費使用額、流用等増△減額、予算決定後移替増△減額（特別会計は、予算総則の規定による経費増額も）、歳出予算現額、支出済歳出額、翌年度繰越額、不用額 |

- 項の CSV（`kou-*.csv`）の金額は、予算書の目の行を項で足した値（目の行数と各金額列の合計）。原本の項の行そのものではない。この仕様では、項の金額の状態を「導出（目の合計）」とする。目の CSV（`moku-*.csv`）は原本の形の行で、第 2 段で目の粒度に降りるときに使う。
- 補正・決算の原本の zip の対応: 補正は一般 `…21001`・特別 `…22001`、決算は一般 `…77001`・特別 `…78001`（`mof-archive/manifest.json`）。
- 金額の列に空欄はない（FY2023・FY2024 の `kou-*.csv` 12 ファイルの全金額セルが整数。空欄 0、整数でない値 0）。負の値は、補正の減少額、決算の流用等・移替に現れる。

## 表

### `kou`（項の識別）

1 行 = 年度 × 項。出来事の表の `kou_id` で結ぶ。

| 列 | 内容 |
|---|---|
| `kou_id` | 年度 + 会計 + 鍵（下）から作る文字列（安定した識別子） |
| `year` | 予算の年度（西暦。令和 N 年度 = 2018 + N） |
| `account` | `general` / `special` |
| `ministry` `org` | 所管・組織（予算書の名前を `nameKey` で揃えたもの）。組織は一般会計だけ。特別会計の所管は、予算書の原文で、複数の府省を「、」「及び」でつないだ文字列のことがある（例: 内閣府、総務省及び財務省）。画面は府省に分けて、所管のフィルタに使う（FY2023・FY2024 で、分けた名前は 1 つを除いて一般会計の所管の名前と一致する。一致しない 1 つは、東日本大震災復興特別会計の「復興庁」で、一般会計の所管には無い） |
| `special_account` `sub_account` | 特別会計の名称・勘定。一般会計は空 |
| `code` `name` | 項コード（予算書のもの）・項名 |
| `seen_in` | その項がある段階（`request` `budget` `supp` `settle` の `;` 区切り） |

### `events`（出来事。値ごと）

1 行 = 項 × 出来事 × 項目（金額 1 つ）。

| 列 | 内容 |
|---|---|
| `kou_id` | 項 |
| `event` | `request`（概算要求）/ `budget`（政府案）/ `supp`（補正。成立と補正後を含む）/ `settle`（決算） |
| `version` | 版。政府案は提出時（`submitted`）。FY2025 のように成立後の版がある年度は、`enacted` も持つ（第 1 段の対象外） |
| `seq` | 同じ種類の出来事の順（補正の号など）。原本に号が無いときは空（下の「補正」） |
| `part` | 決算の特別会計で、同じ項が共管の組織ごとに行を分けるときの組織（`共管所管名|共管組織名`）。それ以外は空 |
| `measure` | 項目名（下の表） |
| `value_orig` | 原本の値（文字列のまま） |
| `unit_orig` | 原本の単位（`千円` / `円`） |
| `value_yen` | 正規化した円（整数）。千円の値は × 1,000 |
| `state` | `original`（原本の値）/ `derived`（導出した値） |
| `source` | 入力ファイル名と行（`kou-general-hosei.csv:123`）。導出の場合は、元の行 |
| `note` | 導出の場合は、導出の元（`目の合計` など） |

- **空欄と 0 を区別する。計算で値を補わない。** 原本に値が無い項目は、行を作らない（0 の行を作らない）。補正のある項に補正の行があることと、補正の無い項に補正の行が無いことは別（後者は「補正が無い」であって、0 ではない）。
- 項の金額は、第 1 段では全部 `derived`（`note` = `目の合計`）。目の粒度では `original`。

### 項目名（`measure`）

| `event` | `measure` | 原本の列 |
|---|---|---|
| `request` | `request_amount` / `request_prev` | 要求額 / 要求書の前年度予算額 |
| `budget` | `budget_amount` / `budget_prev` | 要求額（予算書の列名。特別会計は予定額）/ 前年度予算額（予算書が載せる、補正後の額が多い） |
| `supp` | `enacted_amount` / `supp_add` / `supp_reduce` / `supp_net` / `revised_amount` | 成立予算額 / 補正要求追加額 / 修正減少額 / 差引額 / 改予算額 |
| `settle` | `appropriation` / `carryover_in` / `reserve_use` / `fungible` / `transfer` / `general_provision`（特別会計のみ）/ `current_amount` / `spent` / `carryover_out` / `unused` | 歳出予算額 / 前年度繰越額 / 予備費使用額 / 流用等増△減額 / 予算決定後移替増△減額 / 予算総則の規定による経費増額 / 歳出予算現額 / 支出済歳出額 / 翌年度繰越額 / 不用額 |

- `supp` の `enacted_amount` と `revised_amount` は**累計**の値で、足すと二重になる。号ごとの差額（`supp_net`）は導出ではなく、原本の列（差引額）。

## 項の同一性（同じ年度の中）

段階ごとに項の鍵が少し違うので、決める。

- **鍵:** 一般会計は 所管 | 組織 | 項コード | 項名、特別会計は 特別会計 | 勘定 | 項コード | 項名（名前は `nameKey` で揃える。`names.md`）。概算要求→予算書は、`match.md` の突合（`MATCHED` / `NEAR_NAME`）で `kou_id` に結ぶ。
- **段階をまたぐ項の集合は、揃わない。** 同じ年度でも、政府案・補正・決算で項の集合が違う（下の表）。決算にだけある項が、一般会計で FY2023 193、FY2024 203 ある（補正・移替・予備費使用で、予算の組み替えが起きた項。例: FY2023 の「情報通信技術調達等適正・効率化推進費」は、府省ごとに決算にだけある）。このため、項は政府案の項を土台にせず、**4 段階の項の和集合**を `kou` にする。`seen_in` で、どの段階にあるかを持つ。
- **特別会計の決算は、鍵が一意でない。** 東日本大震災復興特別会計は、同じ（特別会計・勘定・項コード・項名）の行が、共管の組織ごとに複数ある（FY2023 で 288 行・273 鍵、FY2024 で 285 行・272 鍵）。この行を足さず、`part`（共管所管名 | 共管組織名）で別の行にする。政府案・補正の表は、同じ鍵で 1 行。

| 年度・会計 | 政府案 | 補正 | 決算 | 政府案のみ（決算に無い） | 決算のみ（政府案に無い） | 補正のみ（政府案に無い） |
|---|---:|---:|---:|---:|---:|---:|
| FY2023 一般 | 800 | 779 | 975 | 18 | 193 | 11 |
| FY2023 特別 | 243 | 163 | 288 行（273 鍵） | 24 | 54 | 1 |
| FY2024 一般 | 784 | 799 | 978 | 9 | 203 | 24 |
| FY2024 特別 | 250 | 200 | 285 行（272 鍵） | 29 | 51 | 1 |

（項の数は、各 CSV の行数。決算の特別会計は鍵の数で比べた。）3 段階の項の和集合は、FY2023 一般 994・特別 298、FY2024 一般 987・特別 302。

## 検算（恒等式）

作成時に全件で確かめ、結果を `checks` に出す。FY2023・FY2024 の `kou-*.csv` で、次を数えた。

| 式 | FY2023 一般 | FY2023 特別 | FY2024 一般 | FY2024 特別 |
|---|---:|---:|---:|---:|
| 補正: 改予算額 = 成立予算額 + 差引額、かつ 差引額 = 追加額 + 修正減少額 | 779 / 779 | 163 / 163 | 799 / 799 | 200 / 200 |
| 決算: 歳出予算現額 = 歳出予算額 + 前年度繰越 + 予備費使用 + 流用等 + 移替（特別会計は予算総則の経費増額も） | 975 / 975 | 288 / 288 | 978 / 978 | 285 / 285 |
| 決算: 不用額 = 現額 − 支出済 − 翌年度繰越 | 975 / 975 | 288 / 288 | 978 / 978 | 285 / 285 |
| 成立予算額 = 政府案（両方に項がある項） | 768 / 768 | 162 / 162 | 775 / 775 | 199 / 199 |

- 原本の列の中の式は、すべて成り立つ。成立予算額は、政府案と全件一致する（国会の修正が項の額に出ていない。FY2023・FY2024）。

段をまたぐ式。**合わない項があり、原因は未確認。** 合わない項は、理由つきで一覧に出す（`checks`）。

| 式 | FY2023 一般 | FY2023 特別 | FY2024 一般 | FY2024 特別 |
|---|---:|---:|---:|---:|
| 決算の歳出予算額 = 改予算額（補正に項がある。一致 / 違う） | 754 / 20 | 126 / 15 | 774 / 21 | 166 / 14 |
| 決算の歳出予算額 = 政府案（補正に項が無く、政府案にある。一致 / 違う） | 18 / 0 | 78 / 0 | 4 / 0 | 41 / 0 |
| 政府案にも補正にも項が無い決算の項 | 183 | 47 | 179 | 44 |

（特別会計は、決算の鍵が重複する行を除いて数えた。）違う項の例（FY2023 一般）: 内閣府「物価高騰対応地方創生推進費」は、決算の歳出予算額 2,676 億円に対し、補正の改予算額 1.559 兆円。決算では予備費使用 1.131 兆円・移替 −4,037 億円がある。補正の項と決算の項の範囲が違う（予算の組み替え）可能性があるが、確かめていない。

## 年度をまたぐ対応（別の表 `links`）

予算書の前年度予算額は、前年度の補正後の額であることが多い。FY2024 の予算書の一般会計 784 項で、前年度（FY2023）の項と比べた。

| FY2024 の前年度予算額が… | 項数 |
|---|---:|
| FY2023 の改予算額に一致（うち、政府案とは違う） | 738（518） |
| FY2023 の政府案に一致（補正の無い項） | 3 |
| どちらとも違う | 22 |
| FY2023 に項が無い | 21 |

上の表は、FY2023 の政府案に項がある場合の数え方。下の `links` は、FY2023 の補正・決算だけにある項も含むので、「改予算額に一致」が 11 項多い（749 と 738。差の 11 項はすべて、FY2023 に政府案が無い項で確かめた）。

額の一致は、同じ項であることの保証ではない（候補を支える証拠）。対応は別の表 `links` に、根拠つきで持つ。実装は `packages/core/src/lifecycle-links.ts`（`buildLifecycleLinks`。純粋な関数）、出力は `lifecycle-cli.ts` の `links.csv` と、画面用の `lifecycle/data.json.gz` の `links`。

**1 行 = 前の年度の項（`from`）と次の年度の項（`to`）の組。** 同じ会計（一般・特別）の中だけで探す（一般会計と特別会計をまたぐ移管は探していない。未確認）。相手が無い項は、相手の無い行（`UNRESOLVED`）を持つ。

| 列 | 内容 |
|---|---|
| `from_kou_id` `to_kou_id` | 前の年度の項・次の年度の項。相手の無い行は、無い側が空 |
| `evidence` | 根拠（`;` 区切り）: `same_key`（同じ鍵）、`same_name_other_code`（同じ所管・組織で項名が同じ、項コードが違う）、`same_name_other_org`（項名が同じ、所管・組織が違う）、`prev_amount_eq_revised`（次の年度の予算書の前年度予算額 = 前の年度の改予算額）、`prev_amount_eq_budget`（= 前の年度の政府案の額。補正が無い項） |
| `amount` | 前年度予算額の突き合わせの結果（根拠の有無とは別）: `eq_revised` / `eq_budget` / `ne`（どちらとも違う）/ `zero`（前年度予算額が 0。比べない）/ `n/a`（どちらかに値が無い） |
| `status` | 下の規則 |

**探し方と状態の規則:**

1. 同じ鍵の項は結ぶ（`same_key`）。状態は `RESOLVED`。鍵は、このデータの項の識別（鍵は年度・会計ごとに一意）。額の確認（`amount`）は別に持ち、**状態を変えない**。
2. 同じ鍵の相手が無い項（前の側・次の側）について、相手の年度の同じ会計の全項から候補を探す。根拠は `same_name_*` と `prev_amount_eq_*`（前年度予算額が 0 のときは根拠にしない）。同じ鍵の相手がいる項も、候補の相手になる（例: 水道施設整備費は、厚生労働省から国土交通省へ移った。FY2024 の厚生労働省の同名の項は決算だけにあり、同じ鍵で結ばれるが、FY2024 の予算を持つ国土交通省の項は、名前と額の根拠で結ばれる）。
3. 候補の組は、名前の根拠と額の根拠が**両方**あり、前の側・次の側とも、候補がこの 1 組だけなら `RESOLVED`。それ以外（根拠が 1 種類だけ、または候補が複数）は `AMBIGUOUS`。
4. 候補が 1 つも無い項は、相手の無い行を作り `UNRESOLVED`。「項が無くなった」「新しくできた」とは断定しない。

**項ごとの状態**（一覧の「対応」列、フィルタの「対応未確定」）: 確定した対応が 1 つでもあれば「確定」、無ければ、候補があれば「未確定」、候補が無ければ「候補なし」。「対応未確定」は、確定以外の項。

**年度の組ごとの件数**（基準データから。`lifecycle-cli.ts` の出力。同じ鍵 / 候補の組 `RESOLVED`・`AMBIGUOUS` / 相手の無い行 前の年度・次の年度の項。一般会計 | 特別会計）:

| 組 | 同じ鍵 | 候補の組 RESOLVED | 候補の組 AMBIGUOUS | 相手の無い行（前 / 次） |
|---|---:|---:|---:|---:|
| FY2023 → FY2024 | 978 \| 303 | 5 \| 0 | 5 \| 1 | 51 / 35 \| 13 / 14 |
| FY2024 → FY2025 | 820 \| 237 | 4 \| 6 | 7 \| 21 | 193 / 22 \| 63 / 23 |
| FY2025 → FY2026 | 740 \| 264 | 65 \| 1 | 15 \| 7 | 34 / 39 \| 7 / 6 |
| FY2026 → FY2027 | 23 \| 15 | 638 \| 164 | 35 \| 41 | 167 / 6 \| 77 / 1 |

- FY2024 → FY2025 の「相手の無い行（前）」が多いのは、FY2024 に決算にだけある項（約 230）があり、FY2025 の予算書・補正には、同じ項が無いため（決算が無い年度との組）。
- FY2026 → FY2027 は、FY2027 の項が概算要求書だけから作った項（鍵が予算書の項と違う）なので、同じ鍵はほとんど無く、名前と、要求書の前年度予算額（= FY2026 の政府案の額）の組が `RESOLVED` の主体になる。
- 同じ鍵なのに前年度予算額が前の年度のどちらの額とも違う項（FY2023 → FY2024 で一般 22・特別 4 など）は、予算書の前年度予算額が組替え後の額である可能性がある。確かめていない。状態は `RESOLVED` のまま、額の確認を `ne` と出す。
- `AMBIGUOUS` は、名前だけで額の根拠が無い組、または候補が複数の組。同じ項とは断定しない。所管・組織が違う名前だけの根拠は、その名前の項が、同じ鍵の相手が無い側に 1 つだけのときに限る（「予備費」「諸支出金」のように、どの会計にもある名前は、組み合わせが増えるだけなので候補にしない）。
- 概算要求書の前年度予算額（概算要求だけの項。予算書の前年度予算額が無い）は、前の年度の**政府案の額**とだけ比べる（要求書の前年度予算額は当初予算の額で、補正後の額ではない）。予算書の前年度予算額は、前の年度の改予算額と、次に政府案の額と比べる。
- 年度は、`LIFECYCLE_SOURCES` の順に隣り合う年度の組（会計をまたぐ移管は探さない）。

## 導出する値（別の表 `derived`）

表の値と混ぜない。列は `kou_id`、`measure`、`value_yen`、`formula`（式）、`inputs`（元の `events` の行）。

- 査定差（政府案 − 概算要求）、補正の増減（改予算額 − 成立予算額。`supp_net` と一致するはず）、執行率（支出済 ÷ 現額）、不用率（不用 ÷ 現額）。要求側と予算書側の額が両方ある項だけ。
- 概算要求の額は `mof-ui.md` の行の規則（複数書は最も大きい額、統合は足す）を使う。

## 具体例（FY2024 消費者庁共通費、項コード 161、千円）

| 出来事 | 値 |
|---|---|
| 概算要求（`request`） | 要求額 4,991,087（要求書の前年度予算額 4,849,364） |
| 政府案（`budget`） | 5,028,079（予算書の前年度予算額 4,857,523） |
| 補正（`supp`） | 成立予算額 5,028,079、追加額 0、修正減少額 −63,381、差引額 −63,381、改予算額 4,964,698 |
| 決算（`settle`、円） | 歳出予算額 4,964,698,000 = 現額（繰越・予備費使用・流用・移替はすべて 0）、支出済 4,549,176,935、翌年度繰越 0、不用 415,521,065 |

- 恒等式: 5,028,079 − 63,381 = 4,964,698（補正）。決算の歳出予算額 = 改予算額 × 1,000（段をまたぐ式）。4,964,698,000 − 4,549,176,935 − 0 = 415,521,065（不用）。
- FY2025 の予算書の前年度予算額は 4,964,698（= FY2024 の改予算額）、FY2025 の要求書の前年度予算額は 5,028,079（= FY2024 の政府案）。同じ「前年度予算額」でも、予算書は補正後、要求書は当初で、違う。
- 要求書の FY2024 の前年度予算額 4,849,364 と、予算書の 4,857,523 は違う（要求書は FY2023 の政府案、予算書は FY2023 の補正後の額と読めるが、FY2023 のこの項の値で確かめていない。未確認）。

## 未確認・レビューで決めたいこと

1. **出来事の表の形:** 値ごとの長い形（上）にした。理由は、値ごとに状態・出典を持てること、決算の共管の `part` を持てること。0003 の「各列」より行数が増える（FY2023 で 1 万行台）。幅広の形（出来事ごと 1 行）がよいか。
2. **項の金額の状態:** 項の CSV は目の合計なので `derived` にした。原本の項の行（予算書の XML に項の小計があるか）は確かめていない。
3. **補正の号:** 原本の表に号の区別が無い（累計の列のみ）。FY2023・FY2024 の補正予算が第 1 号だけかは確かめていない（推測）。号が複数ある年度に備え、`seq` を持つ。
4. **項の和集合:** 決算にだけある項が約 200 ある。これを `kou` に入れ、`seen_in` で区別する方針でよいか。
5. **共管の `part`:** 東日本大震災復興特別会計の決算を、組織ごとの行のままにした。項ごとの合計を `derived` で出す。
6. **段をまたぐ式の不一致:** 決算の歳出予算額が改予算額と違う項（FY2023・FY2024 で各 14〜21 項）の原因は未確認。
7. **FY2025 以降:** 予算書の提出時と成立後の 2 版があるので、`version` を持つ。決算が無い年度は、`settle` の行を作らない。
