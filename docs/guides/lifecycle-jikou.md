# 予算の一生の画面の「事項」タブ（`#/lifecycle`）

項の下の事項（概算要求・予算書の当初予算と補正）を、年度をまたぐ確定した対応でそろえて、年度の列に並べる。実装は `packages/core/src/lifecycle-jikou.ts`（純粋な関数。テストあり）、`apps/web/src/lifecycle/LifecycleJikouTab.tsx`、データは `packages/pipeline/src/build/lifecycle-jikou.ts`。

```bash
npm run build:data   # lifecycle/jikou.json.gz を、予算の一生の表と一緒に作る
```

## 何を出すか・出さないか

| 段階 | 事項の単位 |
|---|---|
| 概算要求 | FY2023〜FY2027（概算要求書の総表の要求額。`request-jikou-pairing.md`） |
| 政府案（当初予算） | FY2017〜FY2026 |
| 補正 | FY2017〜FY2026（補正の事項の CSV。`mof-history.md`） |
| 決算 | **無い**。決算は項と目の単位で、事項の列が無い。予算書に事項 × 目の額も無いので、目を事項の下には結ばない |

値は 5 つ（千円）: `概算要求`、`政府案`、`補正後`（改予算額）、`補正の差引額`、`前年度予算額`（予算書が載せる）。切り替えて見る。値が無いセルは `—`（0 とは別）。補完しない（補正の記録が無い事項に、政府案の額を補正後として入れない）。要求書の前年度予算額は、事項の単位では出していない。

## データ（`lifecycle/jikou.json.gz`。項の一覧の表示を待たせず、ページを開いたあとに読む。約 0.7MB）

項の一覧の「事項」列（下）と、中ペインの「事項」が使う。読み込み中、一覧の事項の列は「…」。

```text
{ years: number[],
  kous:  string[],      // 項の id（`LifecycleKou.id`）。事項のある項だけ
  nodes: [項の添字, 年度, 事項名, 政府案, 前年度予算額, 補正後, 補正の差引額, 概算要求][],   // 千円。値が無ければ null
  links: [前の年度の事項, 次の年度の事項, 根拠のビット, 額の確認の添字][],                  // 確定（RESOLVED）した対応だけ
  requestRead: number[] }  // 概算要求の事項を読めた項（`kous` の添字）
```

- 事項は 4 種類（`jikouSuppOnly`・`jikouRequestOnly`）: 予算書の事項（当初予算）、補正にだけある事項、概算要求にだけある事項（予算書に無い）。
  - 予算書の事項は、`buildJikouLinkData`（`jikou-links.ts`。`mof-history.md` の「事項の年度をまたぐ対応」）の `nodes`。概算要求の額は、同じ項の同名の事項に載せる。
  - 補正にだけある事項と、概算要求にだけある事項は、別の事項（行）にする。
- 事項を項に結ぶ鍵は、年度・会計・所管（特別会計は特別会計）・組織（特別会計は勘定）・項コード・項名を `nameKey` でそろえたもの。
- 根拠のビットは `JIKOU_EVIDENCE` の添字、額の確認は `JIKOU_AMOUNT` の添字（`lifecycle-jikou.ts`）。
- 結べない事項（項が見つからない）、予算書の事項に置けない概算要求の事項があれば、`build:data` は止まる（捨てない）。重なる項の鍵も止まる。今は 0 件。

### 概算要求の事項

- **予算書の項に対応のある項:** `mof-ui` が項ごとに名前（`pairByName`）でつないだ結果（`mof/detail.json.gz` の `j` と同じ）を使う。両側にある事項は、予算書の事項に要求額を載せる。要求のみの事項は、概算要求にだけある事項として別に持つ。予算のみの事項は、要求額を持たない。要求側の内訳が取れていない項（`noReq`）は、要求額を付けず、`requestRead` に入れない（画面は、予算のみとは言わず、`—` にする）。
- **概算要求にだけある項（予算書に突合できなかった項、FY2027 の項）:** 項の識別は `lifecycle.ts` と同じ。
  - 予算書に突合できなかった項（`reqOnly`・`zero`）は、`mof-ui` の詳細の行から。
  - 予算書が基準データに無い年度（FY2027）の項は、年度推移の事項（`trend-detail` の `jikou.csv`）から。同じ項が複数の要求書に載るときは、要求額の合計が最も大きい公開元の事項だけを使う。
  - 同じ項が複数の行にまとめられた項（`requestOnlyFromMof`）は、最も大きい額の行の事項だけ（項の額の取り方と同じ）。FY2025 の要求側の事項が、`request-jikou-pairing.md` の数より 1 件少ないのは、このため。
- **対応:** 補正にだけある事項と、概算要求にだけある事項の対応は、次の 2 つ。どちらも、すでに確定した対応が出入りしている事項には足さない。当初予算の事項の対応（`links`）は変えない。
  1. 隣り合う年度の同じ鍵の事項と結ぶ（`linkSuppOnly`。`same_key`）。
  2. 項が確定した対応（`lifecycle.links`）でつながるとき、隣り合う年度の同名の事項と結ぶ（`linkExtrasByKou`。`same_name_linked_kou`）。概算要求にだけある項は項コードが無く、鍵では予算書の項と結べないため（例: FY2026 の予算書の項と、FY2027 の概算要求のみの項）。

## 画面

### 中ペインのタブ「項 / 事項 / 目 / RS」

中ペインは、「項」（これまでの一覧）、「事項」、「目」（`lifecycle-moku.md`）、「RS」（`rs-tab.md`）のタブ。右ペインは、選んだタブの詳細（項・事項・目・RS の事業）。以前あった「集計」タブと、項の右ペインの「事項」タブは、2026-10-29 に廃止した。

### 事項の一覧（中ペインの「事項」タブ）

列の並びは、項の一覧に合わせる（所管・会計・組織／勘定・項名、確認済み年度、額、最大額）。説明の文は、この一覧に限らず、画面に出さない（列の見出しや値のツールチップにだけ書く）。決算に事項が無いこと、値が無いこと、対応の注意は、このガイドに書く。

行 = 選んだ年度の事項 1 件（予算書の事項、補正にだけある事項、概算要求にだけある事項。`jikouListRows`）。事項のデータが読み込み前・失敗のときは、その旨を出す。

| 列 | 内容 |
|---|---|
| 所管・会計・組織／勘定・項名 | その事項がある項（項の一覧と同じ） |
| 事項名 | その年度の事項名 |
| 確認済み年度 | 確定した対応でたどれた年度の範囲と年数（`jikouChainNodes`。項が変わった年度も含む）。事業が同じとは限らない |
| 概算要求・政府案・補正後 | 千円の額。値が無ければ「—」（0 とは別）。決算は事項の単位が無いので、列に無い。補正の差引は、一覧には出さない（事項の詳細の表にある） |
| 最大額 | 概算要求・政府案・補正後のうち最大（項の「最大額」と同じ考え方。補正後が歳出予算現額の代わり）。既定の並びの基準 |

- **絞り込み:** 左のフィルタのうち、所管・会計・組織／勘定・項名は、項の一覧と同じ。事項名（部分一致、`.*` で正規表現）は、「事項」タブでは事項名が合う事項に、**「項」タブでは、選んだ年度に事項名が合う事項を持つ項**に絞る（`kouIdsWithJikou`）。事項のデータが届くまでは、事項名を入れていると、項の一覧は「事項を読み込み中…」を出す（絞れないので、絞っていない一覧は出さない）。「値のある段階」「年度をまたぐ対応」は項の絞り込みなので、事項の一覧では使わない。年度は、画面の年度の選択。
- **件数の隣の金額:** 項の一覧は、概算要求・政府案・補正後・決算の合計。事項の一覧は、概算要求・政府案・補正後の合計。値のある行だけを足す（0 は値。ツールチップに、足した行数）。一般会計と特別会計をまたぐ合計は、繰入の分が二重になる。
- **並べ替え:** 列の見出し。既定は最大額の降順。値が無い事項は、向きによらず末尾。列の幅はドラッグで変えられる。上位 600 事項まで出す（選んだ事項が外にあれば、そこまで出す）。
- **選んだ事項:** 項の id と事項名で持ち（保存する）、年度の選択・フィルタを変えると外す。

### 事項の詳細（右ペイン。中ペインが「事項」のとき）

選んだ事項を通る、年度をまたぐ 1 本の流れの、概算要求・政府案・補正後を、グラフと、年度を縦に並べた表で見る（項の事項タブと同じ部品。`JikouViews.tsx`）。年度の列・行を押すと、流れの別の年度の事項に移る（年度も移る）。「この項の詳細を開く」で、その事項がある項を、中ペインの「項」で開く。

### 項の一覧（中ペインの「項」）の「事項」列

項の下の事項の数（その年度。概算要求・予算書の当初予算・補正の事項を合わせた数。`jikouCounts`）。ツールチップに、うち補正にだけある事項と概算要求にだけある事項の数。事項が無い項は「—」（0 とは別）、読み込み中は「…」。列の見出しで並べ替えられる（多い順が先。事項の無い項は、向きによらず末尾）。決算は事項の単位が無いので、決算にだけある項は「—」。

### 項の詳細の「事項」タブ（右ペイン。2026-10-29 に廃止）

事項の選択・段階ごとの額・年度ごとの額・項の額との照合・この項のすべての事項は、画面から無くなった（事項は、中ペインの「事項」で見る）。

### 決算と、予算書が無い年度

**決算は事項の単位が無い。** 決算の XML には事項の行が無く（項と目の単位。`mof-history.md`）、目は事項の下に結べない。グラフと表は、概算要求・政府案・補正後だけで、決算の列は置かない（項の決算は、項の詳細で見る）。

予算書が基準データに無い年度の項（FY2027 の概算要求のみの項）は、概算要求の事項を表に出す（政府案・補正後は `要求のみ`）。

## 限界・未確認

- 概算要求の事項は、名前（`pairByName`）でつないだ結果をそのまま使う。名前が変わった事項は、つながらず、「要求のみ」「予算のみ」の別の行になる（`request-jikou-pairing.md`）。
- 概算要求の事項は、事項の単位の前年度予算額（要求書）を出していない。
- 事項の対応は名前と額の根拠によるので、事業が同じとは限らない（`mof-history.md`）。確定しない事項は別の行になる。
- 概算要求にだけある項と、同じ項が複数の行にまとめられた項で、最も大きい額の書以外の事項は含めない。
- 画面の自動テストは無い。画面は、基準データから作った JSON で動かして確かめた（事項の一覧: 並べ替え、事項名の検索「国際会議」で 15 事項、詳細で年度を移る、項の詳細を開く。初等中等教育振興費の事項の選択（複数選択）・グラフ・表・選んだ事項ごと・照合、一覧の事項の列と並べ替え、概算要求にだけある項、要求のみ・予算のみの事項を含む項、補正にだけある事項を含む項）。
