# ドキュメントの書き方

## 置き場

| 置き場 | 中身 | 寿命 |
|---|---|---|
| `docs/guides/` | 恒久的な仕様（データの契約・つなぎ方・検算・画面の決まり） | 実装と一緒に更新する |
| `docs/decisions/` | 決めたこと。1 件 1 ファイル、理由と、選ばなかった案 | 書き換えず、覆すときは新しいファイルで |
| `docs/notes/` | 作業メモ（設計の検討・調査・計画） | 役目を終えたら消してよい |

- **コードとガイドから `docs/notes/` を参照しない。** メモは消えたり動いたりするので、リンクが切れる。恒久的な内容はガイドか決めたことに書き、コードはそこを指す。
- 決めたことのファイル名は `NNNN-短い名前.md`（例: `0001-repository.md`）。
- メモのファイル名は `YYYYMMDD_HHMM_タイトル.md`（日時は日本時間）。タイトルの直後に 1〜2 行の要約（状態・結論）を書く。索引のファイルは作らない（並行ブランチの衝突の元になる）。

## ガイドの基準: これだけで作り直せること

ガイドは、このリポジトリのコードを見ずに、別のリポジトリで作り直せるように書く（rs-vis などへは、コードではなく指示書で引き継ぐため）。

- **データの契約:** 列・型・単位・鍵・空欄の意味。
- **規則:** つなぎ方、揃え方、例外の扱い。
- **検算:** 恒等式・件数・合計と、その期待値。`tests/golden` などの fixture で再現できるようにし、ガイドから参照する。
- **具体例:** 実際の 1 件を、原本の値で通して示す。

## 書き方

- 長さは中身に合わせる。水増しの節・重複するまとめ・定型の前置きを書かない。
- 事実はデータで裏を取る。取れないものは「未確認」、根拠のない見立ては「推測」と書く。
- コードフェンスには言語タグを付ける（markdownlint MD040）。迷ったら `text`。
- 手元のパスや個人の作業ログを書かない（公開リポジトリ）。
