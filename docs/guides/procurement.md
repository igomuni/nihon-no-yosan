# 調達を観る（調達ポータルの落札実績）

画面「調達を観る」（`#/procurement`）のデータと規則。決めた理由は `docs/decisions/0007-procurement-page.md`。

## 原本

調達ポータル（デジタル庁）の「落札実績オープンデータ」の**全件データ**（CSV）。ページ: `https://www.p-portal.go.jp/pps-web-biz/UAB02/OAB0201`。仕様書: `https://www.p-portal.go.jp/pps-web-biz/resources/app/pdf/rakusatsuopendata.pdf`（取り込んだのは令和 8 年 10 月版）。

- 年度ごとの zip（平成 25 年度〜）。ページの「ダウンロード」は JavaScript で、実体は `https://api.p-portal.go.jp/pps-web-biz/UAB03/OAB0301?fileversion=v001&filename=successful_bid_record_info_all_{年度}.zip`。
- 全件データは、前月末日時点で公表されている落札実績。日次の差分データもあるが、使わない。JSON 形式もあるが、使わない。
- 置き場は `data/download/p-portal/`（git に入れない）。`successful-bid-record/` に zip（原本のまま）、`rakusatsuopendata.pdf`、`manifest.json`（URL・SHA-256・バイト数・行数・取得日時・仕様書の版）。
- 2026-11-10 に取得: 2013〜2026 年度の 14 ファイル、316,281 行。2013 年度は 1 行だけ（2014-03-19 の落札）。2026 年度は、2026-04-01〜2026-11-10 の落札決定日を含む（取得時点で公表済みの分）。

## 原本の形（仕様書 2.1・2.2）

UTF-8（BOM つき）、改行 CRLF、全項目を `"` で囲み `,` で区切る。**ヘッダ行はない**（1 行目からデータ）。列は次の順。

| 列 | 項目 | 形 |
|---|---|---|
| 1 | 調達案件番号 | 19 桁の数字 |
| 2 | 調達案件名称 | 文字列 |
| 3 | 落札決定日 | `YYYY-MM-DD` |
| 4 | 落札価格 | 数字（小数 2 桁。例 `31389000.00`） |
| 5 | 府省コード | 2 桁（例 `W1`）。名前は仕様書 3.1（54 件） |
| 6 | 入札方式コード | 7 桁（例 `8004030`）。名前は仕様書 3.2（16 件） |
| 7 | 商号又は名称 | 文字列 |
| 8 | 法人番号 | 13 桁の数字。空のことがある |

実際の 1 行（2026 年度。落札価格が最大）:

```text
"0000000000000585024","令和８～１０年度双葉町特定帰還居住区域被災建物等解体撤去等及び除染等工事（その４）","2026-05-20","46450000000.00","T1","8002040","前田建設工業株式会社","4010001008789"
```

→ 環境省（`T1`）、一般競争入札・総合評価（`8002040`）、464.5 億円。

## 全行の検査（取り込み時）

14 ファイル 316,281 行の全行で、次を確かめた。`build:data` は、合わない行があれば止まる（捨てない・直さない）。

| 検査 | 結果（2026-11-10 の原本） |
|---|---|
| 全行が 8 列 | 全行 |
| 調達案件番号が 19 桁の数字 | 全行 |
| 案件名・商号又は名称が空でない | 全行 |
| 落札決定日が日付で、ファイルの年度（4 月〜翌 3 月）に入る | 全行（年度ファイル = 会計年度。2013 年度のファイルに 2014-03-19 の行がある） |
| 落札価格が `\d+.\d\d` で、数に直して書き戻すと同じ | 全行 |
| 府省コード・入札方式コードが仕様書の表にある | 全行（データに出るのは府省 45・入札方式 14） |
| 法人番号が空か 13 桁の数字 | 全行。空は 2,841 行（0.9%） |
| 案件番号が複数の年度ファイルにまたがる | 無し |
| 完全に同じ行が重なる | 無し |

- **同じ調達案件番号に複数の行がある**年度がある（年度ごとに 0〜6 案件、0〜13 行。2025 年度が最多で 6 案件・13 行）。複数落札（`8002050`）など。例: 案件 `0000000000000536939`（医療用マスクの購入）は、2 行（1.74 円と 1.77 円）。
- **落札価格は、総額でないことがある。** 円未満が 0 でない行が 1,831 行ある。そのうち 1,443 行は 100 円未満で、単価契約の単価と見られる（例: 上のマスク）。113 行は 100 万円以上で、これは総額と見られる（理由は未確認）。原本の列からは、総額と単価を区別できない。したがって、落札価格の合計は支出の総額ではない。画面は、合計に注意書きを付ける。
- 法人番号が同じで、名称が違う落札者が 7 件ある（名称の表記ゆれ・改称と見られる。未確認）。

## 画面用のデータ（`build:data`）

`npm run build:data` が、`data/download/p-portal/successful-bid-record/` があるときだけ、`apps/web/public/data/procurement/` に作る（git に入れない）。

| ファイル | 中身 |
|---|---|
| `meta.json.gz` | 年度ごとの行数と落札決定日の範囲、府省コード・入札方式コードの名前（仕様書の表の全件）、取得日時、仕様書の版 |
| `{年度}.json.gz` | 年度のファイル。`vendors`（落札者: 名称・法人番号。同じ組を 1 つにまとめる）と `rows`（原本の列の順。落札者は `vendors` の添字） |

- 原本の値は、変えない・補わない。府省コード・入札方式コードは原本のコードのまま（名前は `meta.json.gz` で引く）。落札価格は、数に直す（小数 2 桁まで正確。`toFixed(2)` で書き戻した文字が原本と一致することを、全行で確かめる）。
- 行数 316,281（原本と同じ）。年度ごとの gzip は、最大約 1.5 MB（2024 年度）、全体で約 13 MB。列の定義は、各ファイルの `columns` と目録（`index.json`）にある。
- 作る前に、zip の SHA-256・CSV の SHA-256・行数を、`manifest.json` と照合する。取り込んだ後に原本が変わっていれば、止まる。
- コード表は `datasets/p-portal-code-tables/code-tables.json`（git に入れる。仕様書の PDF から `procurement-codes-cli.ts` で作る。項番が 1 から続くこと、コードが重ならないことを確かめる）。

```bash
node packages/pipeline/src/build/procurement-codes-cli.ts data/download/p-portal/rakusatsuopendata.pdf datasets/p-portal-code-tables/code-tables.json
npm run build:data
```

## 画面

左にフィルタ、中に選んだ年度の一覧、右に詳細（`MofPage` と同じ 3 ペイン）。

- **一覧**: 落札決定日・府省・案件名・入札方式・落札者・落札価格・調達案件番号。見出しの下の集計は、絞り込んだ全行の、行数・府省数・案件数・落札者数・落札価格の合計（ホバーで注意書き）。表示は上位 600 行まで。
- **フィルタ**: 府省・入札方式（選んだ年度に行があるものだけ。件数つき）、案件名・落札者（部分一致か正規表現）、法人番号（すべて・ある・原本が空）、落札価格の範囲（円）。
- **詳細**: 原本の値、同じ案件番号の行（複数あるとき）、同じ落札者の、その年度の落札（上位 30 行と、行数・案件数・合計）。
- **集計行（見出しの下）を選ぶと、右ペインに一覧全体の年度推移**: 今のフィルタを、全年度の落札実績にそのまま掛けた集計。グラフ（落札価格の合計。棒の上のラベルは、選んでいる年度と最大の年度だけ。行数は表だけ）と、年度ごとの表（行数・案件数・落札者数・落札価格の合計）。選んでいる年度の値は、一覧の集計行と同じ（`procurementTrend` が `procurementTotals` と同じ足し方）。年度の行・棒を押す、または J / K で、中ペインの年度が移る。年度のファイルは、集計行を選んだときに、足りない分を読み込む（全年度で約 13 MB）。読み込んでいない年度は「…」、失敗した年度は「失敗」（0 とは別）。落札者数は、年度ごとの数（年度をまたいで数えない）。
- **落札者の同定**: 法人番号があれば法人番号、なければ名称が同じもの（法人番号のある行とは、つなげない）。年度をまたぐ集計はしない（読むのは選んだ年度のファイルだけ）。
- 出典の表示は、画面の下と「出典と利用条件」。

## 載っていないもの

- 公告中・不調の案件、応札者、契約後の変更（原本に無い）。
- 少額のオープンカウンタのうち、個人事業主（調達ポータルの説明）。
- RS（行政事業レビュー）の支出先・契約との照合（**未実施**。法人番号が手がかりになりうるが、一致率は確かめていない）。
- 公告などの他の調達情報: 調達ポータルに一括取得の手段が見当たらない（2026-11-10 に、調達情報検索・事業者情報検索・トップ・サイトマップ・操作マニュアルの一覧を読んで確かめた。検索結果は最大 500 件で、CSV の出力は無い）。

## 利用条件と公開

- 調達ポータルの「ご利用にあたって」（2026-11-10 に本文を読んだ）は、政府標準利用規約（第 2.0 版）に準拠し、CC BY 4.0 と互換で、商用利用も可能とする。出典の記載（`出典：調達ポータル（https://www.p-portal.go.jp/）`）が必要で、加工したときは、そのことも書く。加工したものを、国が作ったように見せない。第三者の権利があるものは、利用者の責任で確かめる。
- `datasets/terms.json` に `p-portal.go.jp`（状態 `gov-terms-2.0`、`page-read`）を入れた。PDL1.0 そのものではないので、別の状態にした。
- **公開サイトには、まだ載せていない。** 公開サイトのデータは、GitHub Releases のデータセットから CI で作る（`web-publish.md`）。落札実績のデータセットは、まだ Releases に置いていない。置くまで、公開サイトの「調達を観る」は、データの読み込みに失敗する（画面は、その旨を出す）。置くときは、`package-rs.ts` と同じ手順で、新しいデータセットとして作る（別の作業）。
