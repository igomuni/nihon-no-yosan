# 過去年度の予算書・決算書（FY2017〜FY2022、財務省の CSV だけ）

概算要求書を基準データに取り込んでいるのは FY2023 以降。それより前の年度は、財務省の予算書・決算書データベース（`www.bb.mof.go.jp`）の公式 CSV だけから、項・目の CSV を作る。「予算の推移」の画面（`#/lifecycle`）に、FY2017〜FY2022 の年度を足す。概算要求の段階は無い（「概算要求書は取り込んでいない年度」と出す。概算要求書が無かったということではない）。

## 作る

```bash
# 入力の zip の記録（名前・SHA-256・バイト数）。取得物から 1 度だけ作る
node packages/pipeline/src/build/mof-archive-cli.ts record <zip のディレクトリ> datasets/mof-history-v0/inputs.json 2017 2018 2019 2020 2021 2022
# 項・目の CSV を作る（記録と違う zip があれば止まる）
node packages/pipeline/src/build/mof-archive-cli.ts build <zip のディレクトリ> datasets/mof-history-v0/inputs.json data/dataset/mof-history-v0 2017 2018 2019 2020 2021 2022
# 画面用のデータを、過去年度つきで作る
npm run build:data:history
```

- zip のディレクトリには `DL{年}{帳票}.zip` が並ぶ。置き場は `data/dataset/mof-history-v0/`（git に入れない。基準データと同じ扱い）。git には、入力の記録 `datasets/mof-history-v0/inputs.json`（zip 44 本）・`jikou-inputs.json`（当初予算の XML の集合 12 帳票）・`jikou-hosei-inputs.json`（補正予算の XML の集合 24 帳票）と、出力全ファイルの SHA-256 `manifest.json`（138 ファイル）を入れる。
- 実装は `packages/pipeline/src/build/mof-archive.ts`。基準データの `mof-archive/` を作った処理と同じ規則（原本の形のまま、`source_row` を足すだけ。項は目を項のキーで集計。歳出の表は見出しに `主要経費別分類コード` を持つ csv）。
- 読む帳票: 当初予算 `11001`（一般）・`12001`（特別）、補正予算 `21xxx`（一般）・`22xxx`（特別）（`xxx` は回）、決算 `77001`（一般）・`78001`（特別）。政府関係機関の帳票（`13001`・`23001`・`76001`）は読まない。歳入の表（`a.csv`）は読まない。
- 出力は `mof-archive/{年度}/`。補正が年度に複数回あるときは、第 1 回が `kou-{general,special}-hosei.csv`・`moku-…`、第 2 回以降が `…-hosei-2.csv`、`…-hosei-3.csv`。

## 確かめたこと

| 確認 | 結果 |
|---|---|
| 同じ処理で、FY2023・FY2024 を作り直す | 基準データの `mof-archive/{2023,2024}/` の 24 ファイルとバイト一致（`datasets/mof-history-v0/reference-comparison.json`、`packages/pipeline/src/migrate/compare-mof-archive.ts`）。FY2023 の zip は、基準データの元の zip と SHA-256 が一致した |
| 見出し | FY2017〜FY2022 の当初・補正・決算の `b.csv` は、年度の文字（`平成29年度`・`令和元年度` など）を除くと、FY2023 と列の数・名前・順序が同じ |
| 原本の列の恒等式 | 補正: 改予算額 = 成立予算額 + 差引額、差引額 = 追加額 + 修正減少額。決算: 歳出予算現額 = 歳出予算額 + 繰越等、不用額 = 現額 − 支出済 − 翌年度繰越。FY2017〜FY2022 の全行で成り立つ。例外は FY2020 の特別会計の決算の 6 行（下。`summary.json` の `identity_fails`）。項の単位では、全項で成り立つ（`checks`: `settle_current`・`settle_unused`） |
| 当初予算の額 = 補正の第 1 回の成立予算額 | 検算 `enacted_eq_budget` は、FY2017〜FY2022 で不一致 0 |
| 補正が複数回ある年度 | 次の回の成立予算額 = 前の回の改予算額は、連続する回に載る項の全部で成り立つ（`supp_chain`。不一致 0） |

FY2018・FY2020 の特別会計の決算（`DL201878001.zip` 60,045 バイト、`DL202078001.zip` 59,170 バイト）は、最初の取得物に無かった。保存してあった年度別アーカイブのページ（`heisei30.html`・`reiwa2.html`）にリンクがあり、財務省のサイトに存在することを確かめて、あとから取得した（取得日 2026-10-25。`https://www.bb.mof.go.jp/server/{2018,2020}/csv/`）。最初の取得物から漏れた理由は確かめていない。他の年度は、保存したページに載る読む対象の帳票が、すべて手元にある。

FY2020 の特別会計の決算の 6 行（上の恒等式の例外）: 労働保険特別会計雇用勘定の 3 つの目（雇用安定等給付金・失業等給付金・育児休業給付金）は、同じ目の行が 2 行ある。2 行目は「流用等増△減額」の列だけに額（負）があり、他は空欄。2 行を足すと、現額の式が成り立つ（例: 失業等給付金 1,484,254,497,000 + 170,000,000,000 − 220,000,000,000 = 1,434,254,497,000）。CSV の行のまま持ち、足さずに、項の単位（目を項で足す）で式を確かめている。2 行目が原本の何を表すか（流用の相手の記載など）は、確かめていない。

## 事項の CSV（FY2017〜FY2022）

財務省の予算書【XML版】（当初予算。一般会計 `{年}11001`、特別会計 `{年}12001`）から、事項（項の下の区分。事業に近い単位）の CSV を作る。`mof-archive/{年度}/jikou-{general,special}.csv`（列は基準データの FY2023〜FY2026 と同じ。年度の文字だけ違う）。説明欄は含めない。

```bash
node packages/pipeline/src/build/mof-jikou-cli.ts record <XML の置き場> datasets/mof-history-v0/jikou-inputs.json 2017 2018 2019 2020 2021 2022
node packages/pipeline/src/build/mof-jikou-cli.ts build  <XML の置き場> datasets/mof-history-v0/jikou-inputs.json data/dataset/mof-history-v0 2017 2018 2019 2020 2021 2022
```

- XML の置き場は、`mof_{年度}/xml/`（XML と `{帳票}menu.html` が並ぶ。前のリポジトリの `data/download_old`）。入力の記録 `jikou-inputs.json` は、帳票ごとの目次・XML の集合（ファイル名と SHA-256 の並び）の SHA-256 と件数。`build` は、記録と違えば止まる。
- 実装は `mof-xml.ts`（前のリポジトリの parser を移したもの。説明は `mof-xml.ts` の冒頭）、`mof-jikou.ts`。規則・文法・失敗の種類は同じで、想定外の構造は止まる（読み飛ばさない）。
- **parser に足したこと**（FY2023・FY2024 の出力は変わらない。下の確認）:
  - 説明欄（11 列目）が無い項の行を受ける（FY2022 の一般会計「船舶建造費」。ほかの列は同じ行と同じ）。
  - 特別会計で、長い表が `<body layer>` ごとの複数の表に分かれるファイルを受ける（FY2017 の東日本大震災復興特別会計）。表ごとに見出しが 1 つあり、すべて同じ型であること、行の順序が頁・行の昇順であることを確かめ、項は表をまたいで続ける。
  - 年度の見出しの文字は、FY2019 の当初予算が「平成31年度」（補正・決算は「令和元年度」）。

### 確かめたこと

| 確認 | 結果 |
|---|---|
| 同じ処理で FY2023・FY2024 を作り直す | 基準データの `jikou-{general,special}.csv` 4 ファイルとバイト一致（`datasets/mof-history-v0/jikou-reference-comparison.json`、`packages/pipeline/src/migrate/compare-mof-jikou.ts`） |
| 項の CSV との突き合わせ（FY2017〜FY2022 の 12 ファイル） | 事項の額の合計が、項の CSV の額と、項ごとに一致。項の集合も一致（一般会計は所管・組織・項コード・項名、特別会計は特別会計・勘定・項コード・項名で。特別会計の所管は、項の CSV が共管の府省をつないだ文字列、事項の CSV が目次の所管で、表記が違うので鍵に入れない） |
| 再現 | 作り直すと、出力 106 ファイルの SHA-256 が同じ |

事項の行数（FY2017〜FY2022、一般・特別）: 1,213・397、1,200・388、1,225・386、1,236・381、1,249・380、1,275・351。

### 限界

- 当初予算の事項（上）と、補正予算の事項（下）。決算の XML には事項の行が無いので、読んでいない（下）。
- 件数の記録（`jikou-inputs.json`）は、parser が最初に読んだ結果で、独立に確かめたものではない。「項との突き合わせ」が、独立の確認。
- 事項の名前が年度をまたいで同じ事業を指すかは、確かめていない（事項に年度をまたぐ対応は作っていない）。

## 補正予算の事項の CSV（FY2017〜FY2024）

財務省の予算書【XML版】の補正予算（一般会計 `{年}21xxx` の「組織別事項別内訳」、特別会計 `{年}22xxx` の「歳出事項別内訳」）から、事項ごとの補正の額の CSV を作る。補正が年度に複数回あるときは、回ごとのファイル（第 2 回以降は `-2`、`-3`）。

```bash
node packages/pipeline/src/build/mof-jikou-hosei-cli.ts record <XML の置き場> datasets/mof-history-v0/jikou-hosei-inputs.json 2017 2018 2019 2020 2021 2022 2023 2024
node packages/pipeline/src/build/mof-jikou-hosei-cli.ts build  <XML の置き場> datasets/mof-history-v0/jikou-hosei-inputs.json data/dataset/mof-history-v0 --reference=data/dataset/reference-v0 2017 2018 2019 2020 2021 2022 2023 2024
```

- 出力は `mof-archive/{年度}/jikou-{general,special}-hosei{,-2,-3}.csv`。FY2023・FY2024 は、基準データ（`reference-v0`）に補正の事項が無いので、このデータセット（`mof-history-v0`）に、補正の事項の CSV だけを置く。
- 列: 当初予算の事項の CSV と同じ識別の列（所管・組織／特別会計・勘定・項コード・項名・事項名・分類コード）、額 5 つ（成立予算額・追加額・修正減少額・差引額・改予算額。千円）、`行の種類`、`source_file`・`source_row`・`source_page`。年度の文字は、補正の見出しのまま（FY2019 は「令和元年度」。当初予算は「平成31年度」）。
- 実装は `mof-xml-hosei.ts`（parser）、`mof-jikou-hosei.ts`、`mof-jikou-hosei-cli.ts`。想定外の構造は止まる。
- **行の種類**: 事項の行は `事項`。項に事項の行が無い（補正の無い）ときは、項の行を `項のみ`（事項名・分類コードは空）として出す。項に事項が 1 つだけのとき、項の行は名前だけで、額は事項の行にある。事項が複数のとき、項の行は小計で、事項の合計と一致するか確かめた（不一致 0）。
- 補正が複数回ある年度（FY2018 2 回、FY2020 3 回、FY2022 2 回）は、回ごとに、その回の補正後の額（改予算額）が入る。次の回の成立予算額は、前の回の改予算額（項の CSV で確かめ済み）。

### 確かめたこと

| 確認 | 結果 |
|---|---|
| 項の CSV との突き合わせ（FY2017〜FY2024 の 24 ファイル） | 項ごとの額（事項の行の合計。事項の行が無い項は項の行）が、項の CSV（`kou-{general,special}-hosei{,-2,-3}.csv`）の 5 つの額と一致。一般会計は全項で一致。特別会計は下の例外を除いて全項で一致 |
| 行ごとの式 | 差引額 = 追加額 + 修正減少額、改予算額 = 成立予算額 + 差引額。全 13,664 行で成り立つ |
| 再現 | 作り直すと、出力の SHA-256 が同じ |

行数: 事項 8,934 行・項のみ 4,730 行。年度ごとの項の数は、`jikou-hosei-summary.json` に残している。

**特別会計の例外（XML に事項の表が無い項）**: 項の CSV にあって、XML の「歳出事項別内訳」に無い項が、特別会計の補正にある。事項の CSV には出さず、年度ごとの `jikou-hosei-summary.json` の `kouWithoutJikou` に残した。
- FY2017 第 1 回: 交付税及び譲与税配付金特別会計の 8 項（01〜07・09）。この回の XML の目次に、この会計の「歳出事項別内訳」の表が無い（歳入と科目別表だけ）。
- 項コード・項名が空の 1 行（東日本大震災復興特別会計。共管 1 つ分の 1 行。例: FY2023 は共管の総務省、成立予算額 62,245,858 千円、補正なし）。FY2017〜FY2024 の特別会計の補正（最終の回）に 1 つずつある。事項の CSV には出ない。

### 決算の XML

決算の XML（`{年}77001`・`{年}72001`・`{年}75001`）には、事項の単位の金額が無い。`77001` の「歳出決算報告書」は組織の合計の表で、`72001` の「歳出」の表は所管・組織・項の単位。項・目の決算額は、CSV（`kou-*-kessan.csv`・`moku-*-kessan.csv`）が同じ粒度。FY2023 の XML の表の題名と、先頭の表を確かめた範囲（全部の表は見ていない）。

## 事項の年度をまたぐ対応と継続年数（FY2017〜FY2026）

事項（当初予算）を、年度をまたいで結ぶ。項の対応（`budget-lifecycle.md` の `links`）と同じ考え方で、根拠と状態つき。

```bash
node packages/pipeline/src/build/jikou-links-cli.ts data/dataset/reference-v0 data/dataset/mof-history-v0 <出力ディレクトリ>   # jikou-nodes.csv、jikou-links.csv、jikou-links-summary.json
```

- 入力: 事項の CSV（当初予算。FY2017〜FY2022 は過去年度のデータセット、FY2023〜FY2026 は基準データ。FY2025 は国会への提出時の版）と、補正の事項の CSV（補正後の額。FY2017〜FY2024。補正が複数回あるときは、その事項が載る最後の回）。FY2025・FY2026 には補正後の額が無い（`prev_amount_eq_revised` は、前の年度が FY2024 以前の組だけ）。
- 実装は core の `jikou-links.ts`（純粋な関数とテスト）、`packages/pipeline/src/build/jikou-links.ts`（読み込み）、`jikou-links-cli.ts`。名前は `nameKey` で揃える。
- **鍵**: 一般会計は 所管|組織|項コード|項名|事項名、特別会計は 特別会計|勘定|組織|項コード|項名|事項名。特別会計の所管は、目次の表記が年度で変わる（例: 関係府省の列挙が増える）ので鍵に入れない（入れると FY2025 の同じ鍵が 300 件、入れないと 330 件）。どちらの鍵も、各年度の中で一意（重複 0）。
- **対応の探し方**（`jikou-links.ts` の冒頭にも書いた）:
  1. 同じ鍵（`same_key`）は結ぶ。`RESOLVED`。
  2. 同じ鍵の相手が無い事項は、相手の年度の同じ会計の全事項から候補を探す。根拠は `same_name_other_item`（同じ所属で、事項名が同じで、項が違う）、`same_item_other_name`（同じ項で事項名が違う。その項の中で、両側とも残りが 1 つだけのときだけ）、`same_name_other_org`（事項名が同じで、所属が違う。その名前が残りに 1 つだけのときだけ）、`prev_amount_eq_revised` / `prev_amount_eq_budget`（次の年度の前年度予算額（0 を除く）が、前の年度の補正後の額 / 当初の額と一致）。
  3. `RESOLVED` は、名前の根拠と額の根拠がそろい、前の側・次の側とも候補がこの 1 組だけのとき。ほかの候補は `AMBIGUOUS`（額だけの根拠も含む）。候補が無い事項は、相手の無い行（`UNRESOLVED`）。会計をまたぐ対応は探さない。
- **継続年数**（`run_years`）: 確定した（`RESOLVED`）対応を、前の年度へ、相手がちょうど 1 つの間さかのぼった年数（その年度を含む、最小 1）。相手が無い・複数・確定でないところで止まる。後ろ（次の年度以降）は数えない。

### 確かめたこと・限界

- 対応の確定（`RESOLVED`）のうち、同じ鍵以外の 138 件の例を数件読んだ。事項名が同じで項コードが変わった組、農業生産基盤整備 → 農業農村整備のような改称（同じ項の中で 1 組だけ残り、前年度予算額が一致）が確定されていた。額だけの根拠（例: 労働保険の予備費と財政投融資の産業投資予備費）は、確定にせず `AMBIGUOUS` のまま。全件の正誤は確かめていない。
- 鍵が同じでも、事項の中身（事業）が同じとは限らない。名称が同じでも組替えで中身が変わる可能性があるが、確かめていない。名称が変わった事業は、鍵が違うので、同じ鍵の対応としては切れる（上の `same_item_other_name` などで拾えるのは一部）。
- 継続年数は、確定した対応だけをたどるので、実際より短く出ることがある（候補が複数のところで止まる）。
- 当初予算の版（提出時か成立後か）は FY2017〜FY2022 で未確認（`mof-history.md` の前の節）。
- 補正後の額は、補正の事項の CSV に載る事項（8,934 行）の分だけ（年度ごとに 825〜1,145 件。補正の無い事項は、当初の額だけで比べる）。

## 予算の一生の表への入れ方

- 年度ごとの入力は `HISTORY_SOURCES`（`packages/pipeline/src/build/lifecycle.ts`）。過去年度のデータセットが無い環境（公開サイトのデプロイなど）では、過去年度は作らない（`lifecycleSources(historyDir)`）。
- **補正が複数回ある年度**: 項ごとに、その項が載る最後の回の行を使う。回が進むと成立予算額は前の回の改予算額になるので、最後の回の改予算額が、その項の補正後の額になる。前の回にだけある項は、その回の行を使う。補正の差引額・追加額・修正減少額は、その最後の回のものだけで、年度の補正の合計ではない（出来事の注に「この項が載る最後の回は第 N 回」と書く）。回をまたぐ合計は作っていない。
- **政府案の版**: 国会への提出時か成立後かを確かめていない。CSV に日付が無い。出来事の `version` は `unconfirmed`（FY2023 以降の基準データは `submitted`）。検算 `enacted_eq_budget` が不一致 0 なので、少なくとも補正の第 1 回の成立予算額とは同じ額（国会の修正が項の額に出ていない可能性。FY2025 は、提出時と成立後で違う項があった）。
- 出典は `history:{年度}/kou-…csv:{行}` の形（基準データの出典と区別する）。
- 概算要求の段階は無い。「概算要求のみの項」も無い。

## 件数（`lifecycle-cli.ts` の出力）

項（一般・特別）は、`lifecycle-cli.ts` の出力で数える。合計は FY2017〜FY2027 で 13,211 項、`events` 174,883 行、`links` 12,916 行。

決算の歳出予算額と補正後の予算額が一致しない項（検算 `settle_eq_revised`）は、各年度に、一般 15〜27、特別 18〜20（決算のある年度）ある（FY2023・FY2024 と同じ傾向。原因は確かめていない）。

## 限界・未確認

- 政府案の版（上）。
- FY2018・FY2020 の特別会計の決算が、最初の取得物に無かった理由。
- 取得元の URL・取得日の記録が無い（URL の形は `https://www.bb.mof.go.jp/server/{年}/csv/{ファイル名}` と推測、未確認）。財務省のサイトから取り直して SHA-256 を比べていない。
- 利用条件は、基準データの財務省のデータと同じ出どころ（`bb.mof.go.jp`、PDL1.0 と出典の表記。`docs/guides/data.md`）として扱っているが、過去年度のデータセットを公開（Releases）するかは決めていない。公開サイトには、過去年度は載らない。
- 項コードが年度をまたいで同じ項を指すかは、`links`（年度をまたぐ対応）の規則で結んでいるだけで、組替えの確認はしていない（一般会計の当初予算で、隣り合う年度の項の 95〜98% は鍵が同じ。名称が変わった項が年に 5〜46 件）。
