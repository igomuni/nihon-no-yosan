# 予算の推移の「目」の一覧（設計案。レビュー前）

項（`budget-lifecycle.md`）と事項（`lifecycle-jikou.md`）に並べて、目の一覧を足す。目は、予算書の項の下の区分（執行の科目）で、当初予算・補正・決算の書にある。この文書は、データを確かめた事実と、その上の表示の案を書く。実装はまだ無い。

## 目の識別と、段階をまたぐ結び方

目の CSV は、基準データの `mof-archive/{年度}/moku-{general,special}{,-hosei,-kessan}.csv`（FY2017〜FY2022 は過去年度のデータセット）。確かめたのは、基準データの FY2023〜FY2025 の一般会計・特別会計（決算は FY2023・FY2024）。

- **キー: 項 + 目名**（一般会計は 所管|組織|項コード、特別会計は 特別会計|勘定|項コード）。当初予算と決算の目を、この組で結ぶ。
  - 結べる割合（一般会計 FY2024）: 当初の 6,716 キーのうち 6,460（96%）が決算にもある。そのうち 6,457 が 1 対 1。特別会計 FY2024 は 1,221 のうち 957（78%）。
  - 決算の「目番号」は、当初の「目別分類コード」とは別のコード体系で、結べない（一般 FY2024: 1 対 1 に結べた組のうち、額が合うのは 1,011 / 1,703。項 + 目名では 4,312 / 6,455。これは補正を足す前の比較）。
  - **項の中で目名が重なる目がある**: 当初で一般 2〜3、特別 4（項の数）、決算で一般 3〜10、特別 7（キーの数）。キーに目名だけでは足りず、分類コード（主要経費別・目的別・使途別）を足す。当初は足すと 1 対 1 になるが、決算の重複は残る（分類コードで分けられるかは未確認）。
- **決算の目名は、括弧つきのものがある**（例: 皇室費の内廷費の目は `(内廷費)`、衆議院予備経費は `(衆議院予備経費)`。項と同名の目）。当初・補正の目名は、括弧が無い、または目名が空の行がある。結び方は、決算の括弧を外したときに結べるかを確かめて決める（未確認）。
- 当初と補正の目名が空の行は、補正の下を参照。

## 補正の目（「外N目」と、項の行）

補正の目の CSV（`moku-*-hosei.csv`）には、目として出してはいけない行がある。

- **「諸謝金外25目」のような集約行**: 補正で変更が無い目を、1 行にまとめた行。確かめたこと:
  - 追加額・修正減少額・差引額が、全行で 0（一般 FY2023 374 行、FY2024 394 行、FY2025 394 行。特別 FY2023 32 行、FY2024 40 行、FY2025 41 行）。
  - 成立予算額は、その項の当初の目のうち、補正に個別の行が無い目の合計と一致する（一般 FY2025 394 / 394、FY2024 393 / 394、FY2023 373 / 374。特別 FY2025 39 / 41）。合わない行の原因は未確認。
  - 名前の N は、目の数と合わないことが多い（一般 FY2024 は 394 行のうち 91 行が、N+1 と違う）。N は数の根拠にしない。
- **目名が空の行**（一般 FY2024 187、FY2025 180。特別 FY2024 134、FY2025 124）: その項の補正の行が 1 つだけで、変更が全部 0、成立額が当初の項の合計と（ほぼ）一致する。補正の目の内訳が無く、項の行だけがある。当初で目が 2 つ以上ある項が含まれる（一般 FY2024 98 項）。

→ **この 2 種類は、補正の目として出さない**。その項の当初の目は、補正が「-」になる。

## 補正で出る目

当初に同じ項・目名が無く、補正の個別の行にある目（成立予算額 0、追加額あり）がある。目名ありの行で、一般 FY2023 64、FY2024 86、FY2025 56、特別 FY2023 1、FY2024 2、FY2025 5。例は会計検査院施設費の「施設整備費」（FY2024、追加 314,468 千円）。→ 当初が「-」、補正に額。

## 決算との整合（結び方の裏取り）

決算の目の「歳出予算額」を、結んだ目の補正との関係で比べた（一般会計。項 + 目名で 1 対 1 のもの）。

| | FY2023 | FY2024 |
|---|---|---|
| 補正の個別行がある目: 決算の歳出予算額 = 補正の改予算額 | 2,110 / 2,124 | 2,233 / 2,246 |
| 補正の個別行が無い目: 決算の歳出予算額 = 当初の額 | 4,421 / 4,444 | 4,273 / 4,297 |
| 当初にも補正の個別行にも無い決算の目 | 411 | 413 |

- 補正の集約行・項の行に入る目は、決算の歳出予算額が当初と同じ。つまり、補正が「-」でも、決算とのつながりは当初の額で説明できる。
- 当初にも補正にも無い決算の目（約 6%）は、決算にだけある目（流用などで現れた目か、目名の違いで結べない目か。内訳は未確認）。→ 当初 -、補正 -、決算に額。

## 概算要求の目（項によって取れ方が違う）

概算要求の目は、概算要求書の明細表から取る（`mof-ui.ts` の詳細の `m`。要求書の目コードは、予算書の目別分類コードとは別で、名前で結ぶ）。突合できた項（FY2023〜FY2026 で 956〜1,035 項）のうち、全部の目で要求と予算書の両側がそろうのは 75〜79%（735〜801 項）。残り 21〜25%（204〜254 項）は、片側にしか無い目がある。要求側の目が 0 の項は 1〜4。

→ 要求の列は、その項の取得状況（全目そろう／一部のみ／要求側の目なし）を併記する。取れなかった目は 0 にせず「-」。

## 表示の案

行 = 目。列 = 当初（政府案）・補正後・補正差引・決算（歳出予算現額・支出済歳出額・不用額）・概算要求。

| 目の状態 | 当初 | 補正 | 決算 | 備考 |
|---|---|---|---|---|
| 補正の個別行がある | 額 | 額 | 額 | |
| 補正の集約行・項の行に入る / 補正が無い項 | 額 | - | 額 | 補正は「変更なし」ではなく、目別の記録が無い |
| 補正で新しく出る | - | 額 | 額 | |
| 決算にだけある | - | - | 額 | |
| 当初にあって決算に無い | 額 | 額 or - | - | 決算に項はあるが目が無い（一般 FY2024 256 目）。原因は未確認 |

「-」は、値が無い（記録が無い）ことで、0 ではない。0 は、観測した 0 のときだけ。

## 実装の順（案）

1. 目の鍵を決める（項 + 目名 + 分類コード。決算の括弧と重複の扱いを確かめる）。
2. `lifecycle/moku.json.gz` を作る（`build:data`。事項の `jikou.json.gz` と同じく、タブを開いたときに読む）。補正の集約行・項の行は入れない。
3. 画面: 一覧のタブに「目」を足し、項の一覧・詳細と同じ操作（フィルタ・並べ替え・選択）。
4. 年度をまたぐ目の対応は、別に決める（目名の変更が多いと推測するが、未確認）。

- 当初にあって決算に無い目、決算にだけある目の内訳。
- FY2017〜FY2022（過去年度のデータセット）で、同じ結果になるか。補正が複数回ある年度は、回ごとの集約の扱い。
- FY2026 の補正の目は 55 行だけで、集約行が無い（補正のあった項だけが載るためと推測）。
