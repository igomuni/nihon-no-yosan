# 予算の推移の「目」の一覧（仕様。レビュー前）

項（`budget-lifecycle.md`）と事項（`lifecycle-jikou.md`）に並べて、目の一覧を出す（予算の推移の中ペインの「目」タブ）。目は、予算書の項の下の区分（執行の科目）で、当初予算・補正・決算の書にある。この文書は、データを確かめた事実と、その上のデータ・画面の仕様を書く。実装は `packages/pipeline/src/build/lifecycle-moku.ts`（データ）、`packages/core/src/lifecycle-moku.ts`（型・一覧・年度の流れ）、`apps/web/src/lifecycle/LifecycleMoku*.tsx`（画面）。

## 目の識別と、段階をまたぐ結び方

目の CSV は、基準データの `mof-archive/{年度}/moku-{general,special}{,-hosei,-kessan}.csv`（FY2017〜FY2022 は過去年度のデータセット）。確かめたのは、基準データの FY2023〜FY2025 の一般会計・特別会計（決算は FY2023・FY2024）。

- **キー: 項 + 目名 + 分類コード**（一般会計は 所管|組織|項コード、特別会計は 特別会計|勘定|項コード。分類コードは、一般が 主要経費別・目的別・財政法公債金対象非対象別・経済性質別・使途別、特別が 財政法公債金を除く 4 つ）。当初予算・補正・決算の目を、この組で結ぶ。
  - 結べる割合（一般会計 FY2024）: 当初の 6,716 キーのうち 6,460（96%）が決算にもある。そのうち 6,457 が 1 対 1。特別会計 FY2024 は 1,221 のうち 957（78%）。
  - 決算の「目番号」は、当初の「目別分類コード」とは別のコード体系で、結べない（一般 FY2024: 1 対 1 に結べた組のうち、額が合うのは 1,011 / 1,703。項 + 目名では 4,312 / 6,455。これは補正を足す前の比較）。
- **項の中で目名が重なる目は、分類コードで分ける**:
  - 当初: 重複キー 一般 FY2023 0・FY2024 2、特別 FY2023・FY2024 とも 4。いずれも、分類コードで分けられる（全件）。
  - 決算（一般）: 重複キー FY2023 10・FY2024 3。いずれも、分類コードで分けられる（全件）。
  - 決算（特別）: 重複キー FY2023・FY2024 とも 7。分類コードだけで分けられるのは 4。FY2023 は、共管所管名・共管組織名を足すと 6 になる（残り 1 は未確認。FY2024 は共管を足したときの数を数えていない）。重複は、東日本大震災復興特別会計の、共管の組織ごとに行がある目に集中する（1 つのキーに 100 行ほどあるものもある）。→ 特別会計の決算は、項と同じく共管の組織ごと（`part`）に分けるか、キーで足し合わせるかを決める（未確認）。
- **括弧つきの目名は、そのまま使う**。`(内廷費)`・`(予備費)`・`(国会予備経費)` のように、項と同名の目、予備費の目は、予算書の目名が括弧つき（当初・補正・決算とも）。決算の括弧つきの目名を、そのまま当初と結べる割合は、一般 FY2023 6/10・FY2024 7/9、特別 FY2023 27/27。括弧を外して初めて結べるのは、一般 FY2023 の 1 件だけで、規則にしない。結べない括弧つきの目は、項名が違う別の目（例: 決算の `(衆議院予備経費)` は、当初に同じ項名の目が無く、`(国会予備経費)` がある）で、名前の表記の違いではない。
- 当初と補正の目名が空の行は、補正の下を参照。

## 補正の目（「外N目」と、項の行）

補正の目の CSV（`moku-*-hosei.csv`）には、目として出してはいけない行がある。

- **「諸謝金外25目」のような集約行**: 補正で変更が無い目を、1 行にまとめた行。確かめたこと:
  - 追加額・修正減少額・差引額が、全行で 0（一般 FY2023 374 行、FY2024 394 行、FY2025 394 行。特別 FY2023 32 行、FY2024 40 行、FY2025 41 行）。
  - 成立予算額は、その項の当初の目のうち、補正に個別の行が無い目の合計と一致する（一般 FY2025 394 / 394、FY2024 393 / 394、FY2023 373 / 374。特別 FY2025 39 / 41）。合わない行の原因は未確認。
  - 名前の N は、目の数と合わないことが多い（一般 FY2024 は 394 行のうち 91 行が、N+1 と違う）。N は数の根拠にしない。
- **目名が空の行**（一般 FY2024 187、FY2025 180。特別 FY2024 134、FY2025 124）: その項の補正の行が 1 つだけで、変更が全部 0、成立額が当初の項の合計と（ほぼ）一致する。補正の目の内訳が無く、項の行だけがある。当初で目が 2 つ以上ある項が含まれる（一般 FY2024 98 項）。

→ **この 2 種類は、補正の目として出さない**。その項の当初の目は、補正が「-」になる。

## 補正で出る目

当初に同じ項・目名が無く、補正の個別の行にある目（成立予算額 0、追加額あり）がある。目名ありの行で、一般 FY2023 64、FY2024 86、FY2025 56、特別 FY2023 1、FY2024 2、FY2025 5。例は会計検査院施設費の「施設整備費」（FY2024、追加 314,468 千円）。→ 当初が「-」、補正に額。

## 決算との整合（結び方の裏取り）

決算の目の「歳出予算額」を、結んだ目の補正との関係で比べた（一般会計。項 + 目名で 1 対 1 のもの）。

| | FY2023 | FY2024 |
|---|---|---|
| 補正の個別行がある目: 決算の歳出予算額 = 補正の改予算額 | 2,110 / 2,124 | 2,233 / 2,246 |
| 補正の個別行が無い目: 決算の歳出予算額 = 当初の額 | 4,421 / 4,444 | 4,273 / 4,297 |
| 当初にも補正の個別行にも無い決算の目 | 411 | 413 |

- 補正の集約行・項の行に入る目は、決算の歳出予算額が当初と同じ。つまり、補正が「-」でも、決算とのつながりは当初の額で説明できる。
- 当初にも補正にも無い決算の目（約 6%）は、**決算にだけある目**。→ 当初 -、補正 -、決算に額（下の内訳）。

### 決算にだけある目の内訳（一般会計）

| | FY2023 | FY2024 |
|---|---:|---:|
| 当初にも補正にも、その項自体が無い | 360 目（183 項） | 364 目（179 項） |
| 項は当初・補正にあり、目だけ決算にある | 51 | 49 |
| 計 | 411 | 413 |

- 項自体が決算にだけある目は、項名に偏りがある。多い順に、FY2023 は 情報通信技術調達等適正・効率化推進費 89 目（75 項）、科学技術イノベーション創造推進費 58、沖縄開発事業費 46、北海道開発事業費 26、南極地域観測事業費 15。FY2024 も同じ顔ぶれ（85・76・48・27・15）。
- 項名からみて、特定の府省が一括して計上し、予算の成立後に各府省へ移した予算（デジタル庁の一括計上予算など）と考えている（ユーザーの見立て。移し替えの手続きは、データでは確かめていない）。これらの項は、各府省の決算に、その府省の項として現れるが、当初・補正の予算書には、その府省の項が無い。
- 決算の「予算決定後移替増△減額」が 0 でない目は、決算にだけある目のうち FY2023 45、FY2024 56 で、一部にとどまる。移替の列だけでは、この目を説明できない（歳出予算額が 0 でない目が、FY2023 342、FY2024 343）。
- → これらも、当初 -、補正 -、決算に額で出す。項の側では、「当初・補正に無い項（決算にだけある）」として、既存の項の一覧の扱い（決算のみ）と同じになる。

## 概算要求の目（項によって取れ方が違う）

概算要求の目は、概算要求書の明細表から取る（`mof-ui.ts` の詳細の `m`。要求書の目コードは、予算書の目別分類コードとは別で、名前で結ぶ）。突合できた項（FY2023〜FY2026 で 956〜1,035 項）のうち、全部の目で要求と予算書の両側がそろうのは 75〜79%（735〜801 項）。残り 21〜25%（204〜254 項）は、片側にしか無い目がある。要求側の目が 0 の項は 1〜4。

→ 要求の列は、その項の取得状況（全目そろう／一部のみ／要求側の目なし）を併記する。取れなかった目は 0 にせず「-」。

## 画面

行 = 目（選んだ年度）。列 = 要求所管・予算所管・会計・組織／勘定・項名・目名・概算要求・政府案・補正後・歳出予算現額・支出済・不用額・最大額。

| 目の状態 | 当初 | 補正 | 決算 | 備考 |
|---|---|---|---|---|
| 補正の個別行がある | 額 | 額 | 額 | |
| 補正の集約行・項の行に入る / 補正が無い項 | 額 | — | 額 | 補正は「変更なし」ではなく、目別の記録が無い。理由はホバー・詳細に出す |
| 補正で新しく出る | — | 額 | 額 | |
| 決算にだけある | — | — | 額 | |
| 当初にあって決算に無い | 額 | 額 or — | — | 決算に項はあるが目が無い（一般 FY2024 256 目）。原因は未確認 |
| 決算の共管別の行 | — | — | 額 | 印「共管」。同じ識別の当初の目は、決算が「—」で、印「決算は共管別」 |
| 概算要求書にだけある目 | — | — | — | 印「要求のみ」。概算要求だけに額 |

「—」は、値が無い（記録が無い）ことで、0 ではない。0 は、観測した 0 のときだけ。値が無い理由（その年度の書が無い、外N目にまとめられた、項の行だけ、補正の無い項、共管別、結べない）を、セルのホバーと右ペインの注記に出す（`mokuSuppNote`・`mokuSettleNote`）。

- **絞り込み**: 項の一覧と同じフィルタ（年度・要求所管・予算所管・会計・組織／勘定・項名）と、目名（正規表現も可）。目名の絞り込みは、項の一覧でも効く（その年度に目名が合う目を持つ項）。「値のある段階」「年度をまたぐ対応」「事項名」は、目の一覧では使わない（項・事項の絞り込み）。
- **右ペイン**: 選んだ目の、年度ごとの概算要求・政府案・補正後・補正差引・歳出予算現額・支出済・翌年度繰越・不用額の表と、その年度の注記（補正・決算の値が無い理由、その項の概算要求の目の取れ方）。年度の流れは、**項の確定した対応でたどった項の中で、同じ識別の目**（無ければ、同じ目名の目がその項に 1 つだけのとき、それを使い「名前」と記す）。目そのものの年度をまたぐ対応（改称・統合）は、まだ作っていない。
- **項の右ペインの「目」タブ**: 選んだ項の目を見る（`LifecycleMokuTab`）。
  - **目の選択とグラフ**: 事項のタブと同じく、目をコンボボックス（チェックボックス付きの複数選択。既定は選んだ年度で一番大きい目）で選び、概算要求・政府案・補正後・決算（支出済）の年度推移を折れ線で見る。2 つ以上選ぶと合計。合計は、額が分かる年度だけ点を描く:
    - 値の無い目が、その段階に無い目（共管別の行とその元の目、概算要求書にだけある目、当初予算に無い目＝補正・決算で出る目）なら、足さずに進める。
    - それ以外で値の無い目（外N目にまとめられた目の補正後、決算に無い目、名前の違う概算要求の目など）があれば、点を描かない。
    - その年度の目を全部選んだときの概算要求・決算は、値のある目を全部足す。概算要求書・決算書の目の行は、どれも目の行のどれか 1 つに置いている（名前の違う目は「要求のみ」の目、共管別は共管別の行）ので、足せば項の額になる。補正後は、外N目にまとめられた目の行が無いので、全部選んでも足せない。
  - **選んだ年度の目**: 概算要求・政府案・補正後・歳出予算現額・支出済・不用額の表（大きい順）。下に**目の計**と**項の額**を並べる。目の計は値のある目だけを足し、値の無い目があれば印（*）を付けて、項の額とは比べない（例: 補正後は、外N目にまとめられた目に値が無いので、項の改予算額に届かない）。値の無い目が無いのに額が違う所は、色を変えて差を出す。
  - **目の年度推移**: 項の確定した対応でたどった年度の、目 × 年度の表。値（概算要求・政府案・補正後・歳出予算現額・支出済・不用額）を切り替える。目は**目名でそろえる**。ただし、同じ目名の目（共管別の行を除く）が 2 つ以上ある年度があれば、その目名は識別（目名・分類コード）でそろえる。共管別の行は識別（共管を含む）でそろえる（`mokuKouTable`）。年度で分類コードが違う目は「名前」と記す。目の改称・統合は見ていない（名前の違う目は別の行）。「·」はその年度に目が無い、「—」は目はあるが値が無い。
  - 目を選ぶと、中ペインの目の一覧で、その目を開く。
- **読み込み**: `lifecycle/moku.json.gz`（約 2.5 MB）は大きいので、目のタブ（中ペイン、または項の右ペイン）を開いたとき、または目名で絞るときに読む。

## データ（`lifecycle/moku.json.gz`）

`build:data` が作る（`LifecycleMokuData`）。

- `nodes`: 目 1 件（1 年度）= [項の添字, 年度, 目名, 分類コード（`|` でつなぐ）, 共管（決算の共管別の行だけ）, 政府案, 補正後, 補正の差引額, 歳出予算現額, 支出済歳出額, 翌年度繰越額, 不用額, 概算要求, 状態のビット]。額は千円。決算は原本が円なので千円に直す（小数になりうる）。
- 状態のビット（`MOKU_FLAG`）: 補正の個別の行がある／外N目にまとめられた／補正は項の行だけ／決算は共管別に分けた／決算の共管別の行／概算要求書にだけある／目名だけで結んだ。
- `suppYears`・`settleYears`・`requestYears`: その段階の書を読んだ年度（この外の年度の「値なし」は、書が無いため）。
- `requestCoverage`: 項ごとの概算要求の目の取れ方（`full`・`partial`・`none`・`noReq`）。概算要求書の項と突合できた予算書の項だけ。

作り方:

1. 当初の目を、項 + 目名（`nameKey`）+ 分類コードで置く。目の項（項の CSV と同じ鍵）が予算の一生の表に無ければ止まる。
2. 補正: 回ごとのファイルを順に読み、目の個別の行の改予算額・差引額を置く（最後に個別の行で載る回の値）。外N目の集約行と、目名が空の行は目にせず、その項の、個別の行の無い目に印を付ける。
3. 決算: 同じ識別の行が 1 つなら、その目に置く。複数なら、共管所管名|共管組織名ごとの行に分け、当初の目には「決算は共管別」の印を付ける（決算は「—」）。
4. 段階の間で識別が合わないときは、その項に同じ目名の目が 1 つだけ（同じ段階でほかの行に結んでいない）なら、目名だけで結ぶ（分類コードが段階で違う目。印を付ける）。それも無ければ、その段階にだけある目として足す。
5. 概算要求: `mof-ui.ts` の詳細の目（要求書の明細の目と予算書の目を、項の中で名前でつないだもの）から、同じ名前の当初の目（1 つだけのとき）に要求額を置く。予算書の目の無い名前は、概算要求書にだけある目として足す。

基準データ + 過去年度のデータセット（FY2017〜FY2026）で、目は 1 年度 8,458〜9,304。全体で、補正の外N目の行 3,814、項の行 5,104、補正にだけある目 733、決算にだけある目 5,173、概算要求書にだけある目 1,535、目名だけで結んだ目 補正 19・決算 18、決算を共管別に分けた識別 38（行 228）。

- 目そのものの年度をまたぐ対応（改称・統合）。
- 補正の集約行の成立額が合わない 1 行（特別は 2 行）の原因。
- 決算にだけある目のうち、一括計上の項（上）と、項は当初・補正にあって目だけ決算にある目（一般 FY2024 49）の、移し替えの手続きと原因。当初にあって決算に無い目の内訳。
