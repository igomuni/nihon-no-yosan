# 予算書の分類コードと、要求書の目のコード

予算書の目には、分類コード（主要経費別・目的別・財政法公債金・経済性質別・使途別・目別）が付く。目の識別（`docs/guides/lifecycle-moku.md`）と、要求書の目を予算書の分類コードに直す規則を、ここに書く。

## 出どころ

- 名称表は、各年度の予算書「(参考) コード番号について」にある定義。前のリポジトリの `docs/mof-budget-data-guide.md` §4 に書き写してあった令和8年度版を移し、基準データ・過去年度のデータセットの目の CSV（FY2017〜FY2026。一般・特別の 22 ファイル）に出るコードと照らした。**表に無いコードが CSV に出る**（各表の下に書く）。名称は、予算書のその年度の定義を見ないと分からず、未確認。
- 予算書の「(参考) コード番号について」の元ページは、令和8年度は一般会計が `202611001001169a.xml`、特別会計が `202612001000521a.xml`（前のリポジトリの記録。`https://www.bb.mof.go.jp/server/2026/…`）。この表の元のページそのものは、このリポジトリでは取得していない。

## 目の CSV の列

- 一般会計（`moku-general.csv`）: 主要経費別（2 桁）・目的別（3 桁）・財政法公債金対象非対象別（1 桁）・経済性質別（2 桁）・使途別（1 桁）・目別（2 桁）。
- 特別会計（`moku-special.csv`）: 財政法の列が**無い**。主要経費別・目的別・経済性質別・使途別・目別。共管所管名・共管組織名の列がある。
- 目の識別（`lifecycle-moku.md`）は、目別を除く分類コード（一般 5・特別 4）+ 目名。

## 複合コードの表記

予算書の本文は、分類コードを連結して印字する。

```text
一般会計:  95016-2111-02
           主要経費別 95 + 目的別 016 ／ 財政法 2 + 経済性質別 11 + 使途別 1 ／ 目別 02
特別会計:  95016-111-02    （財政法の 1 桁が無い）
```

## 要求書と予算書の、目の行の形

| 資料 | 行の種類・形 | 例 | 何か |
|---|---|---|---|
| 要求書の明細表（plain-text。取り込みの `row_type`） | `CODE_5_4_2_4` | `95016‑2111‑03‑0000 職員諸手当` | 目。コードが 5 桁・4 桁・2 桁・4 桁の 4 つ |
| 同上 | `CODE_NN_NNNN` | `03‑0300 通勤手当` | 目の細分。2 桁・4 桁の 2 つ（略記）。上の目から引き継ぐ。目の下に続く |
| 予算書の本文（XML） | `NNNNN-NNNN-NN`（5・4・2） | `95016-2111-02` | 目。4 つ目の桁も、細分の行も無い |
| 予算書の CSV | 列に分解（主要経費別・目的別・財政法・経済性質別・使途別・目別） | — | 目 |

- 行の種類の名前は取り込みのもの（`packages/core/src/request-detail-table.ts` の `RowType`）で、`CODE_NN_NN` も型にあるが、FY2023〜FY2027 のデータには 0 行。`CODE_2_4`・`CODE_5_4_2` という名前は、取り込みに無い（上の表の形を、このガイドで指す呼び名にしない）。行の種類の件数（FY2023〜FY2027 の明細表の全行）: `CODE_5_4_2_4` 133,091・`CODE_NN_NNNN` 46,502・`CODE3`（項）58,049・`CODE2` 9,415・`DETAIL`（事項）9,057・`CONTEXT` 627・`CODE1` 150。
- 予算書の XML の確認: 令和6年度の当初予算（一般会計。`202411001*.xml`）328 件のうち 120 件で、`NNNNN-NNNN-NN` が 3,105 か所。4 つ目の桁がある形と、`NN-NNNN`（細分）の形は 0。328 件の全部に、「通勤手当」は 0 件。

## 要求書の目のコード

要求書の明細表（plain-text）の目の行は、コードを 4 つに分けて持つ。

```text
95016-2111-02-0000 職員基本給
 │     │    │  └ 4 つ目（`0000` など）。予算書に対応する列は無い。意味は未確認
 │     │    └ 目別
 │     └ 財政法 + 経済性質別 + 使途別（一般会計は 4 桁）
 └ 主要経費別（2 桁） + 目的別（3 桁）
```

- 特別会計は、中央が**経済性質別 2 桁 + 使途別 1 桁**（`815` → 経済性質 `81`・使途 `5`）。経済性質別が `00` のときは、使途別 1 桁だけ（`9` → `00`・`9`）。
- 取り込み（`reqMokuClassCodes`、`packages/core/src/mof.ts`）は、桁数が上のとおりのときだけ分類コードに直し、合わない形は補わず空にする。一般会計の中央は FY2024 で全部 4 桁、特別会計は 3 桁か 1 桁だった。
- 中央に **`-` を含む原文は、ハイフンの種類**（`‑` U+2011 を含む）に注意。`reqMokuClassCodes` は両方を受ける。

### 略記の行（目の細分）

目のコードを**全部書く行**（`95016‑2111‑03‑0000 職員諸手当`）の下に、上の目を引き継いだ**略記の行**（`03‑0300 通勤手当`）が続く。略記の行は、目別 `03`・4 つ目 `0300` だけを持ち、主要経費・目的別・中央は上の目から引き継ぐ。

- 取り込みの行の種類は `CODE_NN_NNNN`（目の細分）。全部書く行は `CODE_5_4_2_4`。
- 年度推移の目の CSV（`trend-detail`）には、**細分の行は出さない**。目の額は、目の行の額。目の行が空欄で、すぐ下の細分に額があるときだけ、細分の額を足して目の額にする（CSV の列 `細分の合計を使った行` に数える。FY2023 278・FY2024 241・FY2025 269・FY2026 280・FY2027 222 行）。目の行に額があるときは、細分は内訳として足さない。
- **細分の額と、目の額の関係**（基準データの明細表。目の行ごと）:

  | 年度 | 目に額があり、細分の計と**一致** / 比べられた目 | 目が**空欄**で、細分を使う目の行 |
  |---|---|---|
  | FY2023 | 1,325 / 1,329 | 656 |
  | FY2024 | 1,333 / 1,339 | 603 |
  | FY2025 | 1,161 / 1,162 | 814 |
  | FY2026 | 1,151 / 1,156 | 810 |
  | FY2027 | 1,036 / 1,038 | 661 |

  （要求額の列。前年度予算額の列も、ほぼ同じ割合で一致。細分のどれかが空欄の目は、比べていない。FY2023 3・FY2024 5・FY2025 8・FY2026 6・FY2027 1 行。）
  一致しない目（各年 1〜6 行）は、例: 目 1,773 に対し細分の計 1,695（4 つの細分）。細分に載らない分があるか、細分の読み落としかは未確認。細分は、目の内訳としてほぼ足りている。
- 項の要求額と、目の合計（空欄の目は細分の計を使う）の照合は、項 1,105（FY2023）〜1,188（FY2026）のうち、一致 1,032〜1,135（93〜96%）、一致しない 6〜15、目に空欄がある項 37〜46、目が 1 つも無い項 7〜12（FY2027 は 987 項のうち一致 930・不一致 8・空欄 38・目なし 11）。
- 細分の個々の名前（通勤手当など）と額は、CSV に出ない。予算書の目の CSV（FY2026 の一般・特別）には、細分の名前（通勤手当・管理職手当）の行が 0 件で、目は職員諸手当までで終わる。

## 要求書のコードと予算書の分類コード（実データでの照合）

要求書の目と予算書の目を、同じ項・同じ目名で 1 対 1 に結べたものについて、要求書のコードから直した分類コードが、予算書の主要経費別・目的別・（財政法）・経済性質別・使途別・目別と全部一致するかを見た（基準データ。FY2023〜FY2026）。

| 年度 | 一般会計 一致 / 結べた目 | 特別会計 一致 / 結べた目 |
|---|---|---|
| FY2023 | 7,171 / 7,193 | 1,788 / 1,788 |
| FY2024 | 7,191 / 7,214 | 1,797 / 1,807 |
| FY2025 | 7,612 / 7,632 | 1,806 / 1,860 |
| FY2026 | 7,691 / 7,710 | 1,849 / 1,851 |

外れる目（各年 数件〜50 件）は、要求書のコードが、予算書と**別の主要経費別・目的別や経済性質別**になっているもの（例: 要求書の `63191-815`（経済性質 `81`）に対し、予算書は `40`）。読み方の違いではなく、要求書と予算書で分類が違う目と見られる（原因は未確認）。

## 使い方

- **目の識別に使う**: 概算要求書にだけある項（予算書に突合できなかった項・FY2027 の項）の目に、直した分類コードを付ける。予算書の目と、目名と分類コードの両方で結べる（FY2027 の目 6,878 件のうち 6,658 件が、FY2026 の予算書の目と目名・コードの両方が一致する）。年度をまたぐ対応（`mokuFlow`）は、コードが一致しなければ、目名だけで結ぶ。
- **要求書の目と予算書の目を結ぶ判定には使わない**: 分類のコードは、複数の目に共通で（`pairByName` の注記のとおり、1 つのコードに複数の行が入る）、名前の違う目を結ぶ根拠にならない。予算書の項に突合できた項の、要求書の目は、今までどおり**目名**で結ぶ。
