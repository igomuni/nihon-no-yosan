# 予算書の分類コードと、要求書の目のコード

予算書の目には、分類コード（主要経費別・目的別・財政法公債金・経済性質別・使途別・目別）が付く。目の識別（`docs/guides/lifecycle-moku.md`）と、要求書の目を予算書の分類コードに直す規則を、ここに書く。

## 出どころ

- 分類コードの意味は、各年度の予算書【XML版】の「(参考) コード番号について」のページにある（`https://www.bb.mof.go.jp/server/{年}/xml/`。XML は Shift_JIS）。**コードの意味は年度・帳票ごとに変わる**（次の節）。ページごとの表を、`datasets/mof-code-tables/code-tables.json` に持つ。
- 取り出し: `node packages/pipeline/src/build/code-tables-cli.ts <出力の JSON> <XML のディレクトリ>...`（解析は `packages/core/src/code-tables.ts` の `parseCodeNumberPage`）。XML のセル（`<clm>`）のコードと名称を読み、折り返した名称の行を結ぶ。コードの後に名称が無い・同じ区分でコードが重なるときは止まる（捨てない）。
- 取り出したページ: 37 件（XML 9,554 件のうち）。FY2017〜FY2025 は当初予算（一般・特別）・決算（一般）と、FY2022〜FY2025 の補正予算（一般・特別。FY2022 は第 1・2 号）、FY2026 は補正予算（一般）。XML は、手元にあったもの（`data/download/mof-xml/` の FY2025・FY2026 の補正予算と、前のリポジトリの `data/download_old/mof_{年}/xml/`）。
- **無いページ**: FY2026 の当初予算（令和8年度の当初予算の XML は手元に無い）。特別会計の決算（`78001`）は、XML が手元に無い（FY2017〜FY2025 で確認）。FY2017〜FY2021 の補正予算は、XML（323〜736 件）があるが、コード番号のページが見つからなかった（そのページが無いのか、読めていないのかは未確認）。FY2026 の補正予算（特別会計）の XML（7 件）にも、見つからなかった。
- 各ページに、XML のファイル名と SHA-256 を持つ。年度・帳票・名前の引き方は、`codeName`・`codeNameChanges`。

## コードの意味が、年度・帳票で変わるもの

ページ（年度 × 帳票）の表を並べて比べた（`codeNameChanges`）。変わるのは次のとおり。ほかのコード（財政法・使途別・目別の大半）は、全ページで同じ。

- **所管**: FY2021 にデジタル庁が `07` に入り、総務省以降が 1 つずつ後ろにずれる（総務省 `07`→`08`、防衛省 `17`→`18`）。FY2026 に防災庁が `08` に入り、総務省以降がさらにずれる（総務省 `09`、防衛省 `19`）。所管のコードは、目の CSV の列には出ない（名前だけ）。
- **主要経費別・目的別の予備費**（主要経費別 `93`・`94`・`96`、目的別 `106`・`107`・`108`）: 名称が年度・帳票で変わる。例: `96` は FY2017 の当初予算が熊本地震復旧等予備費、FY2019〜FY2022 が産業投資予備費、FY2026 の補正予算が中東情勢等対応予備費。`94` は、FY2021 の当初予算が新型コロナウイルス感染症対策予備費、FY2023 の当初予算が新型コロナウイルス感染症及び原油価格・物価高騰対策予備費、FY2023 の補正予算が原油価格・物価高騰対策及び賃上げ促進環境整備対応予備費。**同じ年度でも、当初予算と補正予算・決算で名称が違う**（FY2023 の `94`）。`93`（ウクライナ情勢経済緊急対応予備費）は、FY2022 の補正予算第 2 号から FY2024 の補正予算までと、FY2022・FY2023 の決算（FY2024 の決算には無い）に出る。
- **主要経費別の恩給の細目**: `26` 文官等恩給費・`27` 旧軍人遺族等恩給費・`28` 恩給支給事務費・`29` 遺族及び留守家族等援護費は、FY2017〜FY2021 の表にあり、FY2022 から表に無い。
- **経済性質別**: `14` は「現物社会給付等」→「現物社会移転(市場産出の購入)」、`15` は「無基金雇用者社会給付」→「その他の社会保険非年金給付」に、FY2018 から変わる。
- **目的別**（特別会計）: `065` の名称が「物価及び物価調整費」→「物資及び物価調整費」に FY2021 から変わる（表記の訂正と見られる）。
- **目別**: `01` の名称が「職員歳費」（FY2020・FY2021 の決算）→「議員歳費」（FY2022 から）に変わる。目別の表は、FY2020 の決算のページと FY2021 以降のページにある（FY2017〜FY2020 の当初予算のページには、目別の一覧が無い）。

目の CSV に出るコードは、すべて、どれかのページの表に名称がある。**例外は、経済性質別 `00`（5,269 行）と目別 `99`（491 行）で、どのページにも名称が無い**（`00` は、経済性質別が無いことと見られる。要求書のコードでは省く）。

→ 同じコードでも、見る年度・帳票の表で意味が違うことがある。分類コードの名称を出すときは、年度と帳票を指定して、`codeName` で引く。

## 目の CSV の列

- 一般会計（`moku-general.csv`）: 主要経費別（2 桁）・目的別（3 桁）・財政法公債金対象非対象別（1 桁）・経済性質別（2 桁）・使途別（1 桁）・目別（2 桁）。
- 特別会計（`moku-special.csv`）: 財政法の列が**無い**。主要経費別・目的別・経済性質別・使途別・目別。共管所管名・共管組織名の列がある。
- 目の識別（`lifecycle-moku.md`）は、目別を除く分類コード（一般 5・特別 4）+ 目名。

## 複合コードの表記

予算書の本文は、分類コードを連結して印字する。

```text
一般会計:  95016-2111-02
           主要経費別 95 + 目的別 016 ／ 財政法 2 + 経済性質別 11 + 使途別 1 ／ 目別 02
特別会計:  95016-111-02    （財政法の 1 桁が無い）
```

## 要求書と予算書の、目の行の形

| 資料 | 行の種類・形 | 例 | 何か |
|---|---|---|---|
| 要求書の明細表（plain-text。取り込みの `row_type`） | `CODE_5_4_2_4` | `95016‑2111‑03‑0000 職員諸手当` | 目。コードが 5 桁・4 桁・2 桁・4 桁の 4 つ |
| 同上 | `CODE_NN_NNNN` | `03‑0300 通勤手当` | 目の細分。2 桁・4 桁の 2 つ（略記）。上の目から引き継ぐ。目の下に続く |
| 予算書の本文（XML） | `NNNNN-NNNN-NN`（5・4・2） | `95016-2111-02` | 目。4 つ目の桁も、細分の行も無い |
| 予算書の CSV | 列に分解（主要経費別・目的別・財政法・経済性質別・使途別・目別） | — | 目 |

- 行の種類の名前は取り込みのもの（`packages/core/src/request-detail-table.ts` の `RowType`）で、`CODE_NN_NN` も型にあるが、FY2023〜FY2027 のデータには 0 行。`CODE_2_4`・`CODE_5_4_2` という名前は、取り込みに無い（上の表の形を、このガイドで指す呼び名にしない）。行の種類の件数（FY2023〜FY2027 の明細表の全行）: `CODE_5_4_2_4` 133,091・`CODE_NN_NNNN` 46,502・`CODE3`（項）58,049・`CODE2` 9,415・`DETAIL`（事項）9,057・`CONTEXT` 627・`CODE1` 150。
- 予算書の XML の確認: 令和6年度の当初予算（一般会計。`202411001*.xml`）328 件のうち 120 件で、`NNNNN-NNNN-NN` が 3,105 か所。4 つ目の桁がある形と、`NN-NNNN`（細分）の形は 0。328 件の全部に、「通勤手当」は 0 件。

## 事項のコード

事項にも、コードが付く。目と違い、要求書の形（`NN-NN`）と予算書の形が違う。

| 資料 | 形 | 例 | 意味 |
|---|---|---|---|
| 要求書の明細表（`row_type` = `DETAIL`） | `NN‑NN 事項名` | `01‑95 消費者庁一般行政に必要な経費` | 前半は事項の番号（下）、後半は**主要経費別分類コード**（2 桁） |
| 予算書の本文（XML） | 主要経費別分類の 2 桁のセル + 事項名 | `95` + 内閣本府一般行政に必要な経費 | 2 桁は、主要経費別分類コード。事項の番号は無い |
| 予算書の CSV | 一般会計 `主要経費別分類コード`、特別会計 `分類コード` | `95` | 同上 |

- 取り込みの行の種類は `DETAIL`（事項）。型にある `CODE_NN_NN` は、FY2023〜FY2027 の明細表に 0 行で、使われていない。
- **後半は、予算書の事項の主要経費別分類コードと一致する**。項・事項名が予算書と 1 対 1 で結べる事項を比べた（基準データ）:

  | 年度 | 一般会計 一致 / 結べた事項 | 特別会計 一致 / 結べた事項 |
  |---|---|---|
  | FY2023 | 1,168 / 1,168 | 449 / 449 |
  | FY2024 | 1,167 / 1,167 | 473 / 473 |
  | FY2025 | 1,237 / 1,239 | 480 / 482 |
  | FY2026 | 1,254 / 1,256 | 488 / 488 |

  一致しない事項は、FY2025 の一般 2 件と特別 2 件（要求書 `10-05` に対し予算書 `08` など）、FY2026 の一般 2 件。原因は未確認。
- **前半（事項の番号）は、予算書に出ない**。予算書の XML の事項の行は、主要経費別分類コードの 2 桁、事項名、要求額・予算額・比較増△減額（千円）、説明のセルを持ち、番号のセルが無い（令和6年度の当初予算の一般会計の XML で確認）。予算書の「コード番号について」にも、事項に付けるのは主要経費別分類コードと書かれている（令和6年度の当初予算のページの(4)）。したがって、事項を要求書と予算書で結ぶ手がかりにはならない（項の中の事項名で結ぶ）。
- 前半は、項の中の連番ではない。項ごとに `01` から続くとは限らない（FY2023 の要求書の事項 8,783 行で、項 5,583 件のうち連番は 2,882 件）。例: FY2023 の内閣本府共通費の事項は `01‑95`・`06‑95`・`21‑95`・`25‑95`・`41‑95`。同じ組織の通し番号のように見えるが、**未確認**。

## 要求書の目のコード

要求書の明細表（plain-text）の目の行は、コードを 4 つに分けて持つ。

```text
95016-2111-02-0000 職員基本給
 │     │    │  └ 4 つ目（`0000` など）。予算書に対応する列は無い。意味は未確認
 │     │    └ 目別
 │     └ 財政法 + 経済性質別 + 使途別（一般会計は 4 桁）
 └ 主要経費別（2 桁） + 目的別（3 桁）
```

- 特別会計は、中央が**経済性質別 2 桁 + 使途別 1 桁**（`815` → 経済性質 `81`・使途 `5`）。経済性質別が `00` のときは、使途別 1 桁だけ（`9` → `00`・`9`）。
- 取り込み（`reqMokuClassCodes`、`packages/core/src/mof.ts`）は、桁数が上のとおりのときだけ分類コードに直し、合わない形は補わず空にする。一般会計の中央は FY2024 で全部 4 桁、特別会計は 3 桁か 1 桁だった。
- 中央に **`-` を含む原文は、ハイフンの種類**（`‑` U+2011 を含む）に注意。`reqMokuClassCodes` は両方を受ける。

### 略記の行（目の細分）

目のコードを**全部書く行**（`95016‑2111‑03‑0000 職員諸手当`）の下に、上の目を引き継いだ**略記の行**（`03‑0300 通勤手当`）が続く。略記の行は、目別 `03`・4 つ目 `0300` だけを持ち、主要経費・目的別・中央は上の目から引き継ぐ。

- 取り込みの行の種類は `CODE_NN_NNNN`（目の細分）。全部書く行は `CODE_5_4_2_4`。
- 年度推移の目の CSV（`trend-detail`）には、**細分の行は出さない**。目の額は、目の行の額。目の行が空欄で、すぐ下の細分に額があるときだけ、細分の額を足して目の額にする（CSV の列 `細分の合計を使った行` に数える。FY2023 278・FY2024 241・FY2025 269・FY2026 280・FY2027 222 行）。目の行に額があるときは、細分は内訳として足さない。
- **細分の額と、目の額の関係**（基準データの明細表。目の行ごと）:

  | 年度 | 目に額があり、細分の計と**一致** / 比べられた目 | 目が**空欄**で、細分を使う目の行 |
  |---|---|---|
  | FY2023 | 1,325 / 1,329 | 656 |
  | FY2024 | 1,333 / 1,339 | 603 |
  | FY2025 | 1,161 / 1,162 | 814 |
  | FY2026 | 1,151 / 1,156 | 810 |
  | FY2027 | 1,036 / 1,038 | 661 |

  （要求額の列。前年度予算額の列も、ほぼ同じ割合で一致。細分のどれかが空欄の目は、比べていない。FY2023 3・FY2024 5・FY2025 8・FY2026 6・FY2027 1 行。）
  一致しない目（各年 1〜6 行）は、例: 目 1,773 に対し細分の計 1,695（4 つの細分）。細分に載らない分があるか、細分の読み落としかは未確認。細分は、目の内訳としてほぼ足りている。
- 項の要求額と、目の合計（空欄の目は細分の計を使う）の照合は、項 1,105（FY2023）〜1,188（FY2026）のうち、一致 1,032〜1,135（93〜96%）、一致しない 6〜15、目に空欄がある項 37〜46、目が 1 つも無い項 7〜12（FY2027 は 987 項のうち一致 930・不一致 8・空欄 38・目なし 11）。
- 細分の個々の名前（通勤手当など）と額は、CSV に出ない。予算書の目の CSV（FY2026 の一般・特別）には、細分の名前（通勤手当・管理職手当）の行が 0 件で、目は職員諸手当までで終わる。

## 要求書のコードと予算書の分類コード（実データでの照合）

要求書の目と予算書の目を、同じ項・同じ目名で 1 対 1 に結べたものについて、要求書のコードから直した分類コードが、予算書の主要経費別・目的別・（財政法）・経済性質別・使途別・目別と全部一致するかを見た（基準データ。FY2023〜FY2026）。

| 年度 | 一般会計 一致 / 結べた目 | 特別会計 一致 / 結べた目 |
|---|---|---|
| FY2023 | 7,171 / 7,193 | 1,788 / 1,788 |
| FY2024 | 7,191 / 7,214 | 1,797 / 1,807 |
| FY2025 | 7,612 / 7,632 | 1,806 / 1,860 |
| FY2026 | 7,691 / 7,710 | 1,849 / 1,851 |

外れる目（各年 数件〜50 件）は、要求書のコードが、予算書と**別の主要経費別・目的別や経済性質別**になっているもの（例: 要求書の `63191-815`（経済性質 `81`）に対し、予算書は `40`）。読み方の違いではなく、要求書と予算書で分類が違う目と見られる（原因は未確認）。

## 使い方

- **目の識別に使う**: 概算要求書にだけある項（予算書に突合できなかった項・FY2027 の項）の目に、直した分類コードを付ける。予算書の目と、目名と分類コードの両方で結べる（FY2027 の目 6,878 件のうち 6,658 件が、FY2026 の予算書の目と目名・コードの両方が一致する）。年度をまたぐ対応（`mokuFlow`）は、コードが一致しなければ、目名だけで結ぶ。
- **画面の列とフィルタ**（`#/lifecycle`）: 主要経費別・使途別のコードを、中ペインの「目」の列（主要経費・使途別）、「事項」の列（主要経費）に出し、左のフィルタ（主要経費別・使途別。チェックボックス付きの複数選択。項・事項・目のタブで共通）で絞る。コードの名前は、**その年度の当初予算のコード表のページ**（一般会計 `11001`・特別会計 `12001`）から引き、そのページが無い年度（FY2026 の当初予算、概算要求だけの FY2027）は、年度の近いページの名前を使う（ツールチップに書く）。画面用のコード名は `lifecycle/codes.json.gz`（コード表の 2 つの区分だけ。`web-data-cli.ts` が `datasets/mof-code-tables/code-tables.json` から作る）。コードの位置は、目の分類コードのうち、主要経費別は 1 つ目、使途別は一般会計が 5 つ目、特別会計が 4 つ目（財政法の区分が無い。`codesOfMoku`）。実測（FY2024、持っている 37 ページ）: 使途別は 7 区分（`1` 人件費・`2` 旅費・`3` 物件費・`4` 施設費・`5` 補助費・委託費・`6` 他会計へ繰入・`9` その他）で、年度・会計で変わらない。主要経費別は、当初予算で 38〜43 区分、うち 7 つのコードの名称が年度で変わる（`26`〜`29` の恩給関係は FY2022 から無い、`93`・`94`・`96` は予備費の枠で意味が年度で変わる）。
- **要求書のコードの意味は、要求書に載っていない**（要求書にコード表のページは無い。FY2023〜FY2027 の plain-text に、「主要経費別分類」などの語が 0 件）。要求書のコードは、大半が前年度の予算書と同じで、読みも前年度のページの表で足りる。ただし、前年から予算書のコードが変わった目（一般会計 15 件・特別会計 4 件）では、要求書が前年のコードのまま（12 件）と、今年の予算書に合わせたもの（7 件）が混在する（FY2024〜FY2026）。FY2027 の要求書は、FY2026 の予算書（補正予算のページ）で読む。
- **要求書の目と予算書の目を結ぶ判定には使わない**: 分類のコードは、複数の目に共通で（`pairByName` の注記のとおり、1 つのコードに複数の行が入る）、名前の違う目を結ぶ根拠にならない。予算書の項に突合できた項の、要求書の目は、今までどおり**目名**で結ぶ。

## 未確認

- 経済性質別 `00` と目別 `99` の名称（どのページにも無い）。
- 要求書のコードの 4 つ目（`0000`・`0100`・`2010` など）の意味。
- 事項のコードの前半（事項の番号）の意味。要求書の内部の通し番号と見られるが、原文では確かめていない。
- 要求書と予算書で分類が違う目の原因。
- 取り出していないページの、コードの意味: FY2026 の当初予算、FY2017〜FY2021 の補正予算、FY2026 の補正予算（特別会計）、特別会計の決算（上の「出どころ」）。
- 要求の段階で新設されるコード（FY2026 の中東情勢等対応予備費 `96` など）が、要求書にどう書かれているか。
